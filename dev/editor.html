エディタとしての本体

エディタの中核は、タブの配置と、PTY（疑似端末）の実行や出力を結び付けます。会話の記録、画面の保存、実行中のプロセスは別々に扱います。

層の構成#

層受け持つもの
Rust と Tauri PTY、保存、制御 API と OS の窓です。
React と状態管理ワークスペース、配置、入力先、画面の表示です。
WebView本体の画面、Web タブと文書のプレビューです。
ディスク配置、会話との対応、出力や診断の記録です。

データモデル#

画面の呼び名は「ワークスペース > タブ」です。コードの Pane は表示場所、PaneTab はそこに置くタブを表します。保存データと API の名前は変えていません。

型中身
Workspace表示場所の一覧、配置、幅や高さと区切り線の情報です。
Paneタブの一覧と、表示中のタブです。
PaneTab種類、PTY セッション ID、会話 ID と起動の指定です。

端末、ランチャー、Web、文書、オンラインの画面は、タブの種類で区別します。PTY セッション ID は、移動しても作成時の値を使います。ID の先頭から、現在の所属を推測することはできません。

配置の持ち主は workspaceListStore です。実行時の情報は paneMetadataStore、画面の選択は uiStore で扱います。型の名前と画面の名前の対応は用語にあります。

ターミナル#

タブの表示から起動を要求し、同じセッションが生きていれば接続し直します。新しい PTY を作るときは、保存した出力と起動の指定を確かめます。閉じるときは、そのタブの実行を終えます。

出力は、読取、リングへの保存、転送、流量制御、フレーム、xterm の順です。接続の番号である attach epoch を照合し、古い接続の出力を現在の画面へ混ぜません。読めた出力への応答を返し、送り続けて画面を詰まらせないようにします。

tests/test_terminal_binary_transport_contract.py が、転送の契約を確認します。tests/test_ipc_attach_epoch_contract.py が、接続の世代を確認します。これらの検査と、実機の描画確認は別々に行います。

保存#

保存先中身
data.jsonワークスペース、表示場所、タブ、会話 ID と配置です。
scrollback/ PTY の保存された出力です。
WebView の保存領域画面の好みや、その画面の一時的な状態です。

保存はロックの下で読み直し、一時ファイルを同期してから現行ファイルを置き換えます。未来の保存形式を見つけると、書き込みを止めます。保存の担当はリーダー窓で、main の窓に限りません。

窓のまとまり、位置、大きさは、窓の復元情報にも残します。プレビューや一時的な画面が、全部そのまま戻るわけではありません。会話の復元は再開で説明しています。

レイアウトと窓#

見出しは、表示中の名前、「裏 N」、「×」、「⋮」を中心にした 1 段です。同じ表示場所のタブは一覧から選び、別の表示場所へ落とすと加わります。端へ戻すと、分割して隣に並べます。

見出しの空いた場所では、裏のタブごと運べます。引き出して離すといったん別の窓になり、戻すときは窓の帯をつかみます。サイドバーの作業場に約 0.35 秒留まると、その作業場が開きます。

名前のすぐ右の「×」と閉じるキーは、表示中のタブだけを閉じます。右端の「×」は裏のタブもまとめて閉じ、狭いときは「⋮」から同じ操作を選びます。まとめて閉じた後に開き直せるのは、表示中だった 1 つです。

見出しの「右にタブを開く」は既定で表示し、下へ開くボタンも設定で出せます。狭いときは「⋮」から選びます。キーの定義は 38 件で、OS 別の表に載せています。

Windows の切り離した窓には、最小化、最大化と復元、閉じるボタンがあります。Mac の新しい切り離しの帯には、閉じるボタンがあります。作業を戻す操作と、プロセスを終了する操作を区別します。

Web タブとプレビュー#

Web には 7 項目あり、6 サービスと任意のページを開く Browser です。文書のプレビューとは、用途と保存領域を分けます。Windows は WebView2（Web を描くための実行基盤）を使います。

外部サイトの Web タブから、本体の端末やファイルの操作を呼べないように分けています。本体あてのデータの一部を読める経路は残ります。信頼できないサイトは、Web タブで開かないでください。

文書主な表示
HTML JavaScript や相対パスの画像を含む、専用の表示です。
Markdown とテキスト本文を組み立て、テーマに合わせて描きます。
Office文書や表をプレビュー用に組み立てます。
PDF読むための表示です。

Windows のローカル HTML では、文字や図を選んで指摘の下書きを作れます。担当 AI へ貼るのは利用者で、画面や箇所が変わると選び直します。Mac でも Web の撮影と対応する実操作を使えます。

ランチャー#

新しいタブか「⋮」の「新しいターミナルタブ」から、ランチャーを開きます。エージェントは 8 種、Web は 7 項目をカタログから描きます。

Cursor は新規起動に対応しますが、会話は復元せず、再起動するとランチャーへ戻ります。サービスの表示は「使うサービス」で切り替え、記録済みのデータは残します。シェルの起動用コマンドはメモリだけに置き、復元時には再実行しません。入力は 1 行、最大 4,096 UTF-16 コード単位です。

起動先を選ぶと、対応するプロセスや Web タブへ切り替わります。

「Grok Bot (アプリ)」は、導入済みのアプリを開く別の入口です。製品のモデルや effort（考える深さ）は、対応する起動にだけ渡します。任意の追加項目は launcher.local.sh などで管理します。

終了、更新、単一起動#

更新を始める入口は「設定 → アプリ情報 → 更新を確認」です。新しい版があると右上に青い更新マークが出て、どちらも更新するか後にするかを選ぶ確認枠を開きます。Mac の主窓は閉じる操作で隠し、アプリの終了では保存を待ちます。Windows でも、窓と最後のアプリの終了を区別して後片付けします。

同じプロファイルの起動は、OS のロックで判定します。2 個目のプロセスから渡された文書は、稼働中のアプリへ取り次ぎます。

呼び出し元と文書を確かめる#

コードの到達性は、型、登録、呼び出し元、設定の条件を組にして確認します。設計文書だけから、使える機能や未使用のコードを決めません。設計文書と実装で、照合する順番を説明しています。

実機で確かめること#

保存後の再開、窓を戻すときの表示、入力先、Web の権限を確認します。ソースの検査が通ったことと、各 OS の実画面での確認は区別します。
