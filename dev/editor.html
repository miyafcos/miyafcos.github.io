エディタとしての本体（ターミナルを並べて保存する部分）は、端から端まで生きています。Rust のコマンドは 185 件で、登録漏れも同期コマンドの契約違反もありません。端末の出力は、次の順に流れます。

  1. 読み取りスレッド
  2. 256KB のリング
  3. 16ms ごとの転送
  4. 流量制御（未確認 512KB まで）
  5. MCX1 フレーム
  6. attach epoch の照合
  7. xterm

保存は、data.json、scrollback のファイル、WebView の localStorage の 3 系統です。一方で、呼び出し元のない関数や届かない設定が 34 件あります。docs/infrastructure/ の文書は、上流（ptrterminal）時代の記述がほぼそのまま残っています。

このページは、ハーネスと関係なくても成り立つ「エディタとしての mycmux」の仕組みを説明します。上流の cmux-for-linux から受け継いだ部分に、7 月以降の安定化と 9 月の機能が積み重なっています。安定化は遅延 resume、attach epoch、流量制御で、9 月の機能は窓の切り離し、Web ペイン、プレビューです。

どこを触ると何が壊れるかを先に知るために、守るべき約束（契約テスト）を仕組みごとに添えました。

層の構成

層中身
OS のプロセスmycmux.exe 1 個。main スレッドが、イベントループ、同期コマンド 11 件、窓の生成を持つ
tokio ランタイム非同期コマンド 134 件、PTY ごとの転送タスク、scrollback の 10 秒保存、socket、各種の定期処理
専用スレッドPTY ごとの読み取りと書き込み、PTY モニタ、git のブランチ取得 4 本、窓のドラッグ中のカーソル監視（Windows）
WebView main 窓と子窓（mycmux-w<n>）が、同じ React アプリを動かす。Web ペインとプレビューは子 webview（プロファイルごとに別フォルダ）
ディスク%APPDATA% の下のアプリのフォルダに、data.json、バックアップ、scrollback。%LOCALAPPDATA% の下のアプリのフォルダに、WebView のデータと Web のプロファイル。ほかに ~/.mycmux/

起動の順番（src-tauri/src/lib.rs）は、次のとおりです。

  1. --profile を解釈する
  2. panic を diag.log へ書くようにする
  3. 単一起動を確かめる（2 個目は、開くパスを socket で先行プロセスへ渡して終わる）
  4. 親から継いだ一時環境変数 20 個を消す
  5. 状態（AppState の 9 項目）を組む
  6. プラグインを入れる
  7. コマンド 185 件を登録する
  8. setup で、scrollback の保存、状態の配信、livebrief、attention を始める。続けて、ランチャーの書き出し、hook の導入、ailog、PTY モニタ、アカウント、socket を用意する

データモデル

日本語の語彙は「ワークスペース > タブ > ペイン」です。コードの Pane が日本語のタブ、コードの PaneTab が日本語のペインです（英語は日本語の鏡像、docs/adr/0013-vocabulary-workspace-tab-pane.md）。

型持つもの場所
ワークスペース Workspaceタブの一覧、列優先のレイアウト（列ごとのタブの並び）、列幅と行高、手で動かした区切り線の印src/types/workspace.ts:129-154
タブ Paneペインの一覧と、アクティブなペインsrc/types/workspace.ts:100-121
ペイン PaneTab PTY のセッション ID、種類、エージェントの会話 ID、起動時の環境変数などsrc/types/workspace.ts:35-98

PTY のセッション ID は pty-<ワークスペース>-<タブ>-<ペイン> の形で、移動しても作成時の ID を持ち回ります。先頭のワークスペースの部分は、いまの所属とは限りません。

ペインの種類中身PTY
terminal（未指定も同じ）xtermあり
launcher起動先を選ぶ React の画面なし
web子 webview（ChatGPT などのサービス）なし
browser成果物のプレビューなし（ただし tabHasPty() は真を返す）
onlineセーブポイントの一覧なし（同上）
宣言だけのペイン「まだ起動していません」なし（起動の設定が既定でオフ）

tabHasPty()（src/lib/tabLifecycle.ts:35-37）は、web と launcher だけを偽にします。browser と online は真のままです。そのため窓を閉じるときに、存在しない PTY を kill しようとします（Rust が無視するので実害はありません）。

中核の store は 6 つです。

  • workspaceListStore は、レイアウトの唯一の持ち主です。変更はすべて commitLayoutMutation を通ります
  • workspaceLayoutStore は、状態を持たないアクションの束です
  • paneMetadataStore は、PTY ごとの実行時の情報（cwd など）です
  • uiStore は、画面の状態です。名前に反して、activePaneId はペインの PTY の ID です
  • settingsStore は、localStorage に保存する好みです

ターミナル

PTY の一生

  1. ペインが画面に出ると、XTermWrapper が起動の引数をその場で組み直して createSession を呼ぶ。セッションごとに直列化し、attach epoch（どの接続の出力かを示す番号）を予約する
  2. Rust の create_session（src-tauri/src/commands/terminal.rs:77-330）が、まだ生きていない ID のときだけ復元の検証をし、環境変数を掃除して正しい値を入れ直す
  3. SessionManager::create（src-tauri/src/pty/manager.rs:74-152）は、既存の ID なら接続先を差し替えるだけで戻る（reattach）。無ければ、保存済みの scrollback を先読みして PTY を起こし、読み取り、書き込み、転送の 3 つを起動する
  4. 閉じると、kill_session が子プロセスを止め、scrollback のファイルを消す

reattach が起きるのは、次の 3 つの場面です。

  • ワークスペースの切替（同時にマウントするのは 1 つだけ）
  • ペインの切替（マウントするのはアクティブなペインだけ）
  • 窓への切り離しと戻し

出力の経路

  1. PTY の読み取り
  2. 256KB のリング
  3. 転送（64KB、16ms）
  4. 流量制御
  5. MCX1
  6. xterm に書く
  1. 読み取りスレッドが 4KB ずつ読み、OSC 7（シェルが知らせる cwd）を横取りで解析して、リングに追記する。転送キューが満杯なら捨てて、「取りこぼし」の印を立てる
  2. 転送タスクが 64KB までまとめ、流量制御（FrontendFlow）の許可を取る。表示中は、未確認（ACK なし）が 512KB か 16 バッチを超えると待つ。2.5 秒の ACK 待ちが 2 回続くと、自動で読み捨てる
  3. MCX1 フレーム（40 バイトのヘッダと本体）で送る。scrollback のスナップショットは MCS1（24 バイトのヘッダ）
  4. フロントは attach epoch を照合し、古い接続のバッチは ACK だけ返して捨てる
  5. 重複を切って xterm に書き、ACK を 32ms ごとにまとめて返す

守る約束は、tests/test_terminal_binary_transport_contract.py、tests/test_ipc_attach_epoch_contract.py、docs/current-state.md の「Load-Bearing Contracts」です。

入力とその他

  • 入力は 4K 文字ずつまとめて IPC に渡し、混んでいれば順序を保ったまま再試行する。Rust は入力のたびに入力改訂番号を 1 上げ、1KB ずつ書く。socket 経由の送信だけは、条件つきの書き込み（write_to_session_guarded）を使い、注意の印と改訂番号が一致するときだけ書く
  • リサイズは 24、100、240ms の 3 回に分けて合わせる。合わせた直後は、シェルの描き直しが届くまで最大 180ms 画面を隠す（入力欄が浮く見え方を防ぐ）
  • cwd は、OSC 7 と、PTY モニタの 10 秒ごと（全窓が隠れていれば 20 秒）の読み取りで追う
  • xterm は最大 12 個をキャッシュし、アンマウントしても持ち越す

端末設定の検出は、結果が xterm に届いていません。検出するのは、Ghostty、Alacritty、Kitty、Windows Terminal の色とフォントです。テーマの設定が常に優先されるためで、使われているのは Windows のビルド番号だけです。docs/features/implemented/config-detection.md の「既存の端末に見た目を合わせる」は、実際には起きません。

保存

保存先中身書く時機
data.jsonワークスペース、タブ、ペイン、cwd、会話 ID、レイアウト、テーマ、キー設定など変化から 500ms 後に、リーダー窓だけが全体を書く

data.json の書き込みは、次の順で行います（src-tauri/src/db/storage.rs:985-1140）。

  1. プロセス内とプロセス間のロックを取る
  2. ロックの下で読み直す
  3. 一時ファイルに書いて fsync する
  4. 現行のファイルを .bak に複製してから置き換える

知らない版（未来の schema）の data.json を見つけたら、その場でプロセス全体の書き込みを止めます（上書きで壊さないため。8 月下旬の計画を実装済み）。

保存しないものは、プレビュー、セーブポイント一覧、一時のペイン、last_process（常に null）、起動用の一時フィールドです。ワークスペースの状態、最大化、ダッシュボードの状態も保存しません。

data.json を書くのは「リーダー」の窓で、main とは限りません。main が閉じると、残った子窓がリーダーを引き継いで書きます。src-tauri/src/window_registry.rs:11-16 などのコメントは、「main だけが書く」と書いたままです。

また --profile だけでは、本番と分かれないものが 2 つあります。1 つは、main の WebView の localStorage です。もう 1 つは、Windows の data.json 用のロック（名前付き mutex）です。前者は、scripts/test-profile.ps1 が WebView のフォルダを指定して初めて分かれます。

レイアウトと窓

  • 分割、自動均等、最大化: 分割は、新しいタブをランチャーのペインで作る。手で動かした区切り線にだけ印を付け、ほかは分割や閉じるたびに均等に戻す。最大化は Ctrl+Shift+Enter
  • 移動と統合: ペインをタブの中央へ落とすと移動、端へ落とすと分割、タブをタブの中央へ落とすと統合。同じ「動かす」処理が、store のアクションと applyLayoutMutation の 2 本あり、両者を突き合わせるテストはない
  • 窓への切り離しと戻し: ワークスペースやペインを別の窓へ出すと、元の窓は PTY を殺さずにストアから外す。新しい窓が、同じ ID で reattach する。ペイン 1 個だけなら、中身だけの窓（720×520）になる。戻すときは、帯を掴んで main に重ねる。窓の × は、確認のうえ、その窓のペインの PTY を止める（9 月中旬から）
  • フォーカス: src/lib/focusController.ts が、ポインタ、ホイール、キーボード、つまみのクリック、ドラッグ、プログラムのどこから来たかを 1 か所で裁く（守る約束）
  • キーバインド: 39 アクション。上書きは data.json に保存
  • コマンドパレット: Ctrl+P の「セッションを続きから開く」だけ。全アクションを探す汎用のパレットは無い
  • 閉じる確認: タブは、動いているペインがあるときだけ聞く。ワークスペースは毎回聞く。つまみの ×（ペインを閉じる）は、聞かずに PTY を止める

Web ペインとプレビュー

Web ペインと HTML のプレビューは、同じ子 webview の仕組みに乗っています。プリセットは 7 件で、内部用の preview と、次の 6 つです。browser、chatgpt、gemini、claude、notebooklm、grok です。プロファイル（ログイン状態の置き場）は 4 フォルダです。

子 webview の置き場所は、フロントが毎フレーム、画面上のホスト要素の矩形に合わせます。裏で動かす Web ペインは、画面外（-20000, -20000）に置きます（隠すと Gemini の逐次表示が止まるため）。

自動操作は、socket の web.* 19 命令です。Windows だけ、WebView2 のプロセス内の CDP を使います（デバッグ用のポートは開けない）。oracmux がこれを使います。

プレビューの種類表示の仕方
HTML（閲覧）子 webview（プリセット preview）
HTML（編集）iframe
PDFブラウザ内蔵の PDF 表示
Markdown・テキスト・Word iframe の srcDoc（フロントで組み、テーマ色を当てる）
Excel・PowerPoint Rust が書いたプレビュー HTML

エクスプローラや Finder から .md や .html を開くと、2 個目のプロセスが起動します。そのプロセスは、socket で稼働中のアプリに渡して終わります。これは、リポジトリの最新の版の機能で、稼働していた版には無いものです。プレビューのペインは data.json に残らず、再起動すると消えます。

ランチャー

ランチャーは、何も選ばずに作ったタブと、つまみの列の + で開く React の画面です（src/components/workspace/LauncherPane.tsx）。エージェントを選ぶと、MYCMUX_LAUNCH_TARGET、_MODEL、_EFFORT を持つ端末ペインを足して、ランチャーを閉じます。

端末側はシェルを起こし、~/.mycmux/bin/launcher.sh が変数を読んで CLI を起動します。Windows でも Git Bash で動くので、実際に使われているのはこちらです。launcher.sh と launcher.ps1 は、アプリの起動ごとに同梱版で上書きされます。手で直しても、次の起動で戻ります（個人の追加は launcher.local.sh）。

起動できるのはカタログの 13 行（エージェント 7 種と Web 6 種）です。会話の ID を追うのは、claude、codex、claude-codex、grok の 4 種だけです。

終了、更新、単一起動

  • 単一起動: Windows は名前付き mutex、Mac などはロックファイル
  • 終了（Windows）: main の × で確認し、保存し、その窓の PTY を止める。窓が 0 になったら片付ける（保存漏れを足す、scrollback を全部保存、残りの PTY を止める、hook の合言葉を失効）
  • 終了（Mac）: × と Cmd+W は隠すだけ。Cmd+Q は、全窓の保存を待ってから終わる
  • 更新: 設定のアプリ情報にある「更新を確認」だけが呼ぶ。起動時や定期の自動更新の分岐はコードに残っているが、呼び出し元がない

文書と実コードの食い違い

docs/infrastructure/ の 8 本は、どれも 3〜4 月の上流の記述のままです。このページで照合した 4 本は、ほぼそのまま残っています（architecture.md、data-flow.md、frontend-structure.md、rust-backend.md）。8 本の判定は設計文書と実装にあります。

これらの文書は、存在しないファイル 7 件を指しています（TerminalGrid.tsx、PaneHeader.tsx、ThemeSwitcher.tsx、NotificationPanel.tsx、terminalStore.ts、hooks/useWorkspacePersist.ts ほか）。存在しない関数やコマンドも 7 件指しています（save_workspaces、save_settings、updatePaneMetadata、triggerFlash ほか）。コマンドは 8 件と書かれていますが、実際は 185 件です。モニタは 2 秒と書かれていますが、実際は 10 秒と 20 秒です。

docs/current-state.md は、現行版を 9 月上旬の古い版のまま書いています。

コードの中の古いコメントは 9 件あります。代表は、src/components/layout/DetachedPaneShell.tsx:257-260 の「OS で窓を閉じるとペインは main に戻る」です。9 月中旬以降は、確認のうえ PTY を止めます。
