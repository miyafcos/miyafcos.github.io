設計文書と実装の対応

設計の決定と、使える機能はそれぞれの根拠を確かめます。文書の見出しだけから、実装の状態を決めません。

主な設計と実装#

設計や話題配布版での読み方
ADR 0014責務と制御 API の原則です。全工程の実装完了を示すものではありません。
ADR 0015種類ごとの能力と閉じる、移す契約の提案です。実際の終了と移動はソースで確認します。
ADR 0017タブの呼び名と、後続のタブグループの設計です。
エージェント設計読取、比較、点検、HTML の書き出しが実装されています。
エージェントの家独立した標準機能は未実装です。

観測と制御の契約#

状態の根拠、入力の期待値、起動の世代を照合する処理があります。通知、質問の回答、仕事の完了は、別の結果として扱います。観測と操作で、それぞれの入口を説明しています。

段階的な整備の考え方#

既存の操作を保ちながら、状態、識別子、結果不明の扱いを共通にする方針です。計画の段の名前と、個々の修正が配布された事実を混同しません。時期や工程の完了は、決定記録と現在の実装を確かめます。

実装済みの機能#

見出しの 1 段化、裏のタブの一覧、会話の全過去の読取があります。窓の切り離しと復元、Codex の保存 ID による再開も実装されています。再配置には「稼働中だけ」「メインだけ」があります。

受け取り箱、ライブの画面、アカウントの操作 API も使えます。HTML の指摘、エージェント設計の本文や履歴は、それぞれの画面から開きます。利用者向けの説明は最近の変更にあります。

文書の鮮度を確かめる#

README にある数値や手順も、CHANGELOG とソースで照合します。壁紙の配布数、端末フォントの数、上の帯の入口は、実装の定義が根拠です。過去の CHANGELOG の呼び名は、書いたときの語のままです。

古い行番号の付け替えでは、元の引用文を探し、対象の機能を読み直します。版の見出しや数だけを追って、別の機能の根拠へ移しません。

設計段階のもの#

タブグループは、現在の表示場所の説明と区別します。横だけの配置へ移る工程や、グループの提案を、すでに使える機能とは書きません。現在の画面には右や下へタブを開く操作が残っています。

コード側から確かめるもの#

状態の読取、窓の所有者、未保存の資料の終了を、実装の処理と試験で確認します。ACP などの試験設定は、標準の操作と区別します。実行時の入口に、制御 API の追加をまとめています。

確認の範囲#

ソースでつながる処理と、実機で測った結果を分けます。窓の配置、再開の失敗、外部 Web の権限は、OS と環境を示して確認します。
