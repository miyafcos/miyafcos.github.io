ディスパッチと結果の確認

委譲は、別のエージェントに仕事を任せる手順です。本体はタブの起動、送信、読取、終了を出し、仕事の分け方は利用者の手順で決めます。

全体の地図#

依頼の目的、変更してよい範囲、完了条件を、起動前に文書へまとめます。委譲先をタブで開き、途中でも人が会話を確認できる形にします。結果の提出と、依頼元が確かめて採る検収を区別します。

委譲 1 件の流れ#

  1. 相手へ渡す指示書と、成果物の保存先を決めます。
  2. 対応する種類と、起動の指定を確認します。
  3. 制御 CLI で起動し、返ったタブとセッション ID を記録します。
  4. 会話と成果物を読み、必要なら追加の指示を送ります。
  5. 完了条件を確認し、結果を採ってから片づけます。

既定の起動先は、呼び出し元と同じ表示場所の裏です。--split で、別の表示場所へ並べる指定もできます。タブが別の窓に移っても、制御 API は持ち主の窓へ操作を届けます。

記録と完了の回収#

記録では、仕事の名前と、実際に起動したタブや実行の ID を分けます。完了報告だけで検収済みとは扱わず、成果物と検査の出力を照合します。依頼元が動いている間の子の完了は、「委譲元の確認待ち」と表示します。

追加指示の送信#

相手の状態、起動の世代、入力の改訂番号を確かめて送ります。send --enter は Enter を 1 回だけ送ります。配送を確かめられない場合は不明として返し、自動では再送しません。

本文を入力しただけの段階と、送信を確定した段階も区別します。指示が受理されたことは、仕事が完了したことを意味しません。

質問と判断#

人が決める必要のある問いは、対象、選択肢、止まる理由をまとめて渡します。質問への回答は、まだ有効な相手と状態へだけ送ります。利用者の個人の質問経路と、本体の質問カードを混同しないでください。

見守りと自動化#

委譲の見守りは、判断待ちや検収の失敗、未送信の入力を知らせる機能です。見守りの表示だけで、再送や終了が済んだとは扱いません。外部の常駐スクリプトの運用は、その環境で別に確認します。

実行契約カード#

目的、素材、役割、完了条件を確認するカードです。「GO」までプロセスやブランチを作らず、素材の取得に失敗していれば進めません。開始後も、結果の統合、検査、人の承認をそれぞれ確認します。

起動、送信、終了の約束#

操作確認すること
起動対応するエージェントと、適用できるモデルや effort です。
送信宛先の実行、入力の状態、結果不明の扱いです。
読取画面の範囲と、読んだ時刻です。
終了タブの種類、未保存の資料、閉じる対象です。

Grok の引き継ぎによる起動は、通常の起動と同じ auto の権限です。ドラッグで別の会話へ下書きを渡す操作では、Grok は対象外です。対応できない指定を、別の意味の起動へ黙って替えません。

しおりからの引き継ぎ#

文脈の引き継ぎは、しおりと、しおりからのドラッグで行います。タブや切り離した窓を表示場所の中央に落とすと、引き継ぎを出さずにタブとして合流します。

設計と、現在の確認の範囲#

委譲の保存領域や権限の将来設計は、ADR の決定と実装を照合して読みます。既存のタブの操作が使えることと、設計の全工程が完成したことは別です。立ち位置と約束に、読み分け方があります。
