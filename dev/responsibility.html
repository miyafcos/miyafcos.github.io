立ち位置と約束

mycmux は、複数のエージェントをタブで動かす作業場です。操作と記録の整合を本体、製品固有の形式をアダプター、仕事の方針を手順に置きます。この原則は設計の方向で、全工程の実装が完成したという説明ではありません。

原則を置く理由#

異なる製品でも、起動、状態、送信、結果の確認を共通の約束で扱うためです。利用者の仕事の判断や、製品内部の実行ループまで本体へ持ち込みません。確かめられない結果を、保証したものとして表示しません。

5 つの領域#

領域受け持つこと
エージェント製品対話、道具の実行、権限と会話の記録です。
アダプター起動の引数、hook、会話 ID と対応する機能です。
mycmux 本体タブ、PTY、保存、状態、画面と制御 API です。
手順やスキル任せる先、待ち方、やり直し、評価です。
利用者とプロジェクト規則、許可、モデルの選び方と品質の基準です。

本体と手順の受け持ち#

操作の相手と、何を記録したかの整合は、本体に置く方針です。仕事の分け方、レビューの方法、何を採るかは、手順と利用者が決めます。保存した質問と回答、配送と確認も、別の事実として扱う設計です。

設計のルール#

  1. 製品固有の形式を、アダプターへ閉じ込めます。
  2. 対応できる機能と、隠せない制限を示します。
  3. 手順は、公開された制御 API を使います。
  4. 残す事実の持ち主を決めます。
  5. 操作と記録の整合、仕事の方針を分けます。
  6. 未対応は、別の意味の成功へ替えません。
  7. 連携の導入と、利用者の設定の変更を明示します。
  8. 観測の出所、確度と不明な範囲を示します。
  9. 報告や画面の文字を、親への命令へ格上げしません。
  10. 用語を、同じ意味で使います。

識別子と状態#

タブ ID、PTY セッション ID、会話 ID、起動の世代を区別します。質問と送信の期待値も、現在の相手と照合します。古い実行への回答を、新しい実行へ流さないための区分です。

ターンの終わり、仕事の完了、成果の検収も別の状態です。出力がない時間は観測で、停止や完了の証明そのものではありません。

エージェントごとの差#

新規起動はカタログの 8 種に対応します。Cursor も新規起動できますが、会話の復元には対応しません。会話の追跡と再開は、その全種類が同じ対応ではありません。Claude の effort、Codex の保存 ID、Grok の通常の権限を、それぞれの経路で扱います。

未知の指定や、適用できない起動の組み合わせは、起動前に断ります。「求めた値」「渡した値」と、製品への適用を確認した値を区別します。再開の対応に、入口ごとの差があります。

受け渡しの約束#

ADR は、実行、導入、能力と認証、保存の約束を分けて定義しています。使う側は、入力、対象、成り立つ条件、結果不明の扱いを確認します。現在の実装の範囲は、境界とソースで照合します。

操作区別する結果
起動指定の検査、起動の受付、相手の準備です。
状態観測した証拠、判定、不明です。
送信本文の入力、確定、受理と結果不明です。
質問回答の保存、配送、確認と解決です。
結果提出と検収です。
再開同じ会話の再開と、新しい会話への引き継ぎです。
終了ターンの中断、プロセスの終了、タブを閉じる操作です。
連携導入、入切、解除と所有する設定です。

同じ OS 利用者の権限で動くプロセスからの完全な隔離は、各製品の実行環境に委ねます。共通の約束の範囲と、製品のサンドボックスの範囲を読み分けます。

現在の実装と、段階的な変更#

版と能力の照会、起動指定、Enter の 1 回化、全件の状態の取得は実装されています。窓を移した相手への操作と、全種類のタブの終了にも対応しています。委譲の保存と権限の設計の全工程が完了した、と読み替えるものではありません。

設計で残る論点#

タブグループは後続の設計で、現在の表示場所の操作と区別します。エージェントの家、記録の持ち主、保持と片付けも、それぞれの設計を照合します。構造化された接続の試験と、標準の起動を混同しません。

確認と既知の制限#

休止候補と新しい作業中判定は、まだ同じ処理ではありません。外部 Web のデータの読み取りの経路も、一部残っています。まとめて閉じたタブの開き直しは、表示中だった 1 つだけです。

各 OS の入力、窓、復元の結果は、対象の環境を示して確認します。ソースと検査の成功、実機の確認を別の証拠として残します。

読み取りの画面と仕事の判断#

エージェント設計は、設定や文書を読む入口です。本文、履歴、HTML の設計書を扱い、除外する記憶や鍵の範囲を示します。点検の記録がないことだけで、未使用や削除可能とは決めません。
