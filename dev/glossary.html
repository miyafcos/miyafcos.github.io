mycmux では、同じ語が別々のものを指している箇所が多くあります。「ディスパッチ」は 9 通り、「カード」は 9 通り、「resume」は 13 通りに使われていました。「引き継ぎ（handoff）」は 5 通り、「session id」は 6 通り、「判断」は 12 通りです。このページは、その見分け方と、ガイドで使う基本の語をまとめたものです。

このガイドは、読む人が文書の外を見なくても分かるように、語を初めて使うところで一言の説明を添えています。それでも、コードの識別子と日本語の呼び名がずれていたり、同じ語がアプリとハーネスで別の意味だったりします。そのため、ここに一覧を置きます。

基本の語

語意味
ワークスペース > タブ > ペイン日本語の階層（正本は docs/adr/0013-vocabulary-workspace-tab-pane.md）。タブは画面を割った区画 1 つ、ペインはセッション 1 つ
Pane と PaneTabコードの識別子。Pane は日本語のタブ、PaneTab は日本語のペイン（英語は日本語の鏡像）。日本語で書くとき、識別子から訳さない
つまみタブの上に並ぶ、ペインの札
アプリmycmux 本体（Rust の Tauri と、React のフロント）
ハーネスClaude Code・Codex・Grok の設定と、作者の skill・hook・スクリプト・台帳・規則（~/.claude/ ほか）
橋両方にまたがる部品（socket・CLI・bridge・hook の helper・環境変数の約束・スキルパック）
親作者と話している Claude のセッション。委譲を出す側
子親が別のペインに立てた、新しいセッション
便委譲 1 回分（ペイン 1 つの起動）の記録の単位
socketアプリが localhost で受け付ける命令の口（1 行 1 JSON）
hookエージェントがイベントのたびに呼ぶスクリプト。アプリの hook は状態を知らせ、ハーネスの hook は注入、遮断、記録をする
PTYペインの中で動く疑似端末
注意の印（attention）ペインが人に気づいてほしい状態（入力待ち・承認・完了・使用量の上限など）
リーダー窓data.json を書き、socket の命令を実行する窓。main とは限らない

「resume」と「引き継ぎ」と「session id」

  • resume（13 通り）: CLI の resume、アプリの自動再開、休眠からの復帰、Ctrl+P、続きから、Ctrl+Shift+T、--resume-session。複製、引き継ぎ、セーブポイントの参加、ハーネスの resume-inject（会話は再開しない）。要約の md の Resume Command、識別子の名前（詳しくは resume）
  • 引き継ぎ（5 通り）: Ctrl+P の引き継ぎ書（~/.crsm/handoff/）、セーブポイントの handoff.md、Web ペインの引き継ぎ書（~/.mycmux/handoff/）。親の手書きメモ（~/.claude/dispatch/session-handoffs/）、プロンプト付きの spawn（委譲の spec を配るだけでも、引き継ぎの経路と文面を使う）
  • session id（6 通り）: PTY の ID（MYCMUX_PANE_SESSION_ID、socket の --session）。ペインの ID（対応表と scrollback のキー）と、会話の ID（--resume-session）。旧名の claude_session_id、Ctrl+P の索引の ID、セーブポイントの ID
  • restore: レイアウトの復元のこと。会話の再開は、ペインを開いたときに、起動のコマンドの側で起きる

組違い
委譲の見守りと見張り前者はアプリの通知の機能、後者はハーネスの常駐（休止中）
commands/agent_prompts.rs と ~/.mycmux/agent-prompts/前者は hook の承認への応答、後者は CLI のプロンプトの置き場
session_state と ~/.mycmux/sessions/どちらも保存の仕組みではない（前者はメモリ上の状態、後者は成果物の置き場）
hooks_dispatch と session-dispatch前者は hook の振り分け、後者は委譲
気づき列の内部 ID __mycmux_report_inbox__報告インボックスは削除済み。名前だけ残っている
