mycmux では、同じ語が別々のものを指している箇所がたくさんあります。「ディスパッチ」は 9 通り、「カード」は 9 通り、「resume」は 13 通りに使われていました。「引き継ぎ（handoff）」は 5 通り、「session id」は 6 通り、「判断」は 12 通りです。以下の表で、その見分け方と、ガイド全体で使う基本の語を整理しています。

ガイドの各ページでは、語を初めて使うところに短い説明を添えています。それでも、コードの識別子と日本語の呼び名がずれていたり、同じ語がアプリと作者の運用で別の意味だったりするので、一覧をここに置きます。

基本の語

語意味
ワークスペース > タブ > ペイン日本語の階層（正本は docs/adr/0013-vocabulary-workspace-tab-pane.md）。タブは画面を割った区画 1 つ、ペインはセッション 1 つ
Pane と PaneTabコードの識別子。Pane は日本語のタブ、PaneTab は日本語のペインに当たる（英語は日本語の鏡像）。日本語で書くときは、識別子から訳さない
つまみタブの上に並ぶ、ペインの札
アプリmycmux 本体（Rust の Tauri と、React のフロント）。立ち位置の説明では「mycmux 本体」と書く
エージェント製品利用者がターミナルで動かす AI の CLI 製品。Claude Code、Codex CLI、Grok CLI、Antigravity CLI、Hermes、Oh My Pi など
エージェントハーネス製品の内部で、モデルの周りのツール実行、文脈、権限、実行ループを受け持つ基盤（Claude Agent SDK など）。mycmux は触らない。「ハーネス」はこの意味にだけ使う
作者の運用作者の ~/.claude/ ほかにある skill、個人の hook、スクリプト、台帳、rules の総称。9 月 24 日の版では「ハーネス」と呼んでいた
エージェントの設定ファイル製品が読む設定。~/.claude/settings.json、~/.codex/hooks.json、~/.grok/config.toml など
エージェント別アダプター製品ごとの起動と再開の引数、hook の導入、会話 ID の取得、能力の申告を受け持つコード。利用者向けには「エージェント連携」と呼ぶ
制御 API mycmux の操作と照会の約束。socket は通り道、JSON Lines は書式、CLI は利用プログラム、MCP は出し方の 1 つ
インターフェースアプリと外側の境界の約束。いまは制御 API（socket）、hook の申告、環境変数、スキルパック（skill の配布）の 4 つ
skill Agent Skills 形式の手順書と補助スクリプト。仕事の進め方を渡す（session-dispatch、mycmux-bridge、oracmux）
ブリッジ別の口へ中継する実行物（mycmux-bridge）
指示文書エージェント向けの指示の Markdown（CLAUDE.md、AGENTS.md）。拡張の仕組みとは分けて扱う
実行ペインの中で動いている 1 回の起動。同じペインでも、起動し直せば別の実行
親セッション仕事を任せる側の実行。いまは、作者と話している Claude のセッション
子セッション任された側の実行。親セッションが別のペインに立てる
委譲タスク親セッションが子セッションに任せる仕事 1 件。委譲 1 回分（ペイン 1 つの起動）の記録の単位
質問子が人の判断を求める 1 件。権限の承認やログインの要求とは別の種類。いまの判断カードに当たる
socketアプリが localhost で待ち受ける窓口。コマンドを 1 行 1 JSON で受け付ける
hook製品の中の出来事を外へ知らせる仕組みで、形式は製品ごとに違う。アプリの hook は状態を知らせ、作者の個人の hook は注入、遮断、記録をする
PTYペインの中で動く疑似端末
attentionペインが人に気づいてほしい状態（入力待ち・承認・完了・使用量の上限など）
リーダー窓data.json を書き、socket のコマンドを実行する窓。main とは限らない

「橋」「器」「便」「合言葉」「関所」は使いません。境界の約束はインターフェース、変換するコードはアダプター、中継する実行物はブリッジと呼び分けます。

「ディスパッチ」の 9 つの意味

呼び名意味持ち主
session-dispatch と委譲タスク親セッションから子セッションへの委譲skill
見張り（dispatch_guard.py）委譲タスクとペインの停止を検出する常駐プロセス（9 月中旬から停止中）スクリプト
hooks_dispatch hook のイベントを、複数のスクリプトへ振り分ける入口個人の hook
dispatch モジュール（委譲の見守り）台帳を読んで通知する、アプリの機能アプリ
dispatchBatchダッシュボードの @ で、複数のペインに同じ指示を配るアプリ
dispatch_outbox WorkOrder が出す spawn の予定アプリ
requiresLauncherDispatchランチャー経由で起動するかの判定アプリ
dispatchKeyEvent などDOM のイベント、Web ペインの自動操作アプリ
socket コマンドの振り分け受けたコマンドを、処理関数へ回す表アプリ

session-dispatch と Rust の dispatch モジュールは、名前が似ていますが別物です。

呼び名誰が決めるか

reconciler も 2 つあります。ADR 0010 の agent_state の reconciler は hook の入口にある受付の検査で、画面に効く状態を決めているのは session_state です。

「resume」と「引き継ぎ」と「session id」

  • resume（13 通り）: CLI の resume、アプリの自動再開、休眠からの復帰、Ctrl+P、続きから、Ctrl+Shift+T、--resume-session。複製、引き継ぎ、セーブポイントの参加、個人の hook の resume-inject（会話は再開しない）。要約の md の Resume Command、識別子の名前（詳しくは resume）
  • 引き継ぎ（5 通り）: Ctrl+P の引き継ぎ書（~/.crsm/handoff/）、セーブポイントの handoff.md、Web ペインの引き継ぎ書（~/.mycmux/handoff/）。親セッションの手書きメモ（~/.claude/dispatch/session-handoffs/）、プロンプト付きの spawn（委譲の spec を配るだけでも、引き継ぎの経路と文面を使う）
  • session id（6 通り）: PTY の ID（MYCMUX_PANE_SESSION_ID、socket の --session）。ペインの ID（対応表と scrollback のキー）と、会話の ID（--resume-session）。旧名の claude_session_id、Ctrl+P の索引の ID、セーブポイントの ID
  • restore: レイアウトの復元のこと。会話の再開は、ペインを開いたときに起動コマンドの側で起きる

名前が似ている別物

組違い
委譲の見守りと見張り前者はアプリの通知の機能、後者は作者の常駐スクリプト（停止中）
commands/agent_prompts.rs と ~/.mycmux/agent-prompts/前者は hook の承認への応答、後者は CLI のプロンプトの置き場
session_state と ~/.mycmux/sessions/どちらも保存の仕組みではない（前者はメモリ上の状態、後者は成果物の置き場）
hooks_dispatch と session-dispatch前者は hook の振り分け、後者は委譲
気づき列の内部 ID __mycmux_report_inbox__報告インボックスは削除済みで、名前だけが残っている
