エディタの中核の外にある仕組みは、ほとんどが調査当日も動いていました。AI ログ、使用量、アカウント切替、履歴、ポケット、セーブポイント、ランチャーの候補、ペインの整理、ペットです。

アプリが LLM を呼ぶ経路は 2 つしかありません。CLI（codex exec か claude -p）を子プロセスとして起動する経路と、Jev を OpenRouter の API で呼ぶ経路です。

アカウント切替は、エージェント製品の認証ファイル（~/.claude/.credentials.json、~/.codex/auth.json、~/.grok/auth.json）を書き換えます。history.db（2.88GB）は書き込まれるだけで、読む経路がどこにもありません。

ターミナルと委譲の外にある機能を、1 つずつ見ていきます。8 月に AI ログ、使用量、アカウント切替が入り、9 月には Jev による再配置と、ポケット mycmux への一本化が入りました。作者の運用（~/.claude にある skill、hook、スクリプト、台帳）にも、似た役目のものがあります。日報、statusline、要約で、重なりもあわせて書きます。

AI ログ（ailog）

AI ログは、Claude Code、Codex、Grok の会話の記録を SQLite に増分で索引する機能です。量、費用（従量課金ならいくらになるかの参考値）、手戻り、モデル別の集計を出し、タイトルバーの AI ログのボタンから開きます。

  • 取り込み元は、~/.claude/projects、~/.codex/sessions、~/.grok/sessions と、アーカイブ ~/.mycmux/ailog-archive/（作者のスクリプト session_archive.py が書いた gz）。起動 120 秒後から 6 時間ごとに、「増分索引 → Google ドライブへの全文ミラー」を回す
  • ~/.mycmux/ailog.db は 1.26GB、40,049 セッション（Claude 9,591、Codex 30,282、Grok 176）
  • LLM による要約はボタンからしか実行できず、最後の実行は 8 月下旬。日次ダイジェストには、画面から呼ぶ入口がない

claude-codex の会話（~/.claude-codex/config/projects の 178 本）は、ミラーには入るのに、元の場所からは索引されません。索引に入るのは、アーカイブ ~/.mycmux/ailog-archive/claude-codex に退避された分だけです。価格表には GPT-6 世代の 2 つのモデルがなく、これらのモデルの費用は 0 円になります。

自動命名の判定の会話 1,352 件は、利用者の作業として集計に混ざっています（作業フォルダが、アプリの起動フォルダになっているため）。保持期限と削除の処理はありません。

使用量とアカウント切替

使用量の機能は、登録した CLI のアカウントごとに、5 時間枠や 7 日枠などの使用率を各社の API から取得します。API は次の 3 つです。

  • Claude は https://api.anthropic.com/api/oauth/usage
  • Codex は https://chatgpt.com/backend-api/wham/usage
  • Grok は https://cli-chat-proxy.grok.com/v1/billing

画面側で、一覧を 60 秒ごと、使用量を 180 秒ごとに取得します。socket の account.usage で外にも公開していて、作者の birdseye スクリプトがこれを読みます。

アカウント切替は、CLI のログインを複数保存しておき、ワンクリックで差し替える機能です。ここは、アプリとエージェント製品の境界そのものに当たります。

  1. 今のログインを持ち主の控えへ
  2. 対象の控えを検証
  3. 現物をバックアップ
  4. エージェント製品の認証ファイルを置き換え
対象アプリが書くもの条件
Claude ~/.claude/.credentials.json を丸ごと置き換え（Mac は Keychain）、~/.claude.json の oauthAccount だけ差し替え切替のとき
Codex ~/.codex/auth.json を置き換え切替のとき
Grok ~/.grok/auth.json を置き換え切替のときと、使用量の取得でトークンが更新されたとき

追従（live_sync）は、20 秒ごとに認証ファイルの変化を見て、控えを取り直します。どのアカウントにも属さないログインは、自動で登録します。

Claude では、名前とトークンを別々のプロセスが書きます。そこで、トークンを profile API に渡して持ち主を確かめてから振り分けています（9 月中旬の取り違えの再発防止）。控え 15 個とバックアップ 10 世代は、%APPDATA% の下のアプリのフォルダに平文の JSON で置かれています。

履歴 history.db

livebrief が会話の記録を読むたびに、イベントを SQLite に書き込みます。全文検索（FTS5）の索引と、ターンごとの機械的なまとめ（読んだファイル、書いたファイル、コマンド、テストの結果）も作ります。8 月中旬に導入され、40 日で 2.88GB、約 89 万イベントになりました。

読む経路がありません。検索の関数（history::search）はどこからも呼ばれず、テストが下位の検索を使っているだけです。画面、socket、skill のどこからも読まれていません。まとめの「意味づけ」の列は常に空のまま書かれ、保持期限と削除の処理もありません。

ポケット mycmux

設定のポケットのタブを開くと、tailscale serve status --json から /pocket の配信を探し、実際に応答するかを確かめてから QR を出します（src-tauri/src/pocket.rs）。

ポケット本体は、別リポジトリ（~\pocket-mycmux\server.py）の常駐サーバです。スケジュールタスク PocketMycmux-Serve で動き、socket（status.subscribe、session.state_view、bridge の answer-ask）を使います。旧来の内蔵サーバ（7682 番）は 9 月中旬に削除され、~/.mycmux/remote.port と remote-token は使われないまま残っています。

ポケットの要件（docs/mobile-chat-design-260829.md）は「送信は一切しない」（R9）でした。ところがポケットには、Gmail の下書きを実際に送る API（POST /pocket/api/mail/send）があります。README には「取り消し不可。UI は 2 段タップを挟むが、API 単体では 1 回で送る」とあり、要件を改訂した記録は見つかっていません。

セーブポイント

セーブポイントは、Claude と Codex の作業を「引き継ぎの記録」として共有フォルダに保存する機能です。記録の中身は manifest.json、handoff.md、会話の記録で、別の場所で要約から始めるか、記録ごと fork して続けます。ペインを別のペインへドラッグして引き継ぐ操作も、この仕組みを使っています。

記録ごと続けるときは、会話の記録をエージェント製品の保存先（~/.claude/projects、~/.codex/sessions）に複製し、claude --resume <新> --fork-session か codex fork を起動します。Python の CLI 3 本（scripts/savepoint_*.py）は同じ形式を保つ約束になっていますが、アプリからも skill からも呼ばれていません。

共有ワークスペース（feat/shared-workspace ブランチ）は、これとは別物です。こちらは「同時に画面を映す」機能で、master に合流しないまま 97 コミット遅れています。このブランチは、master が 9 月中旬に削除した src-tauri/src/remote/ の上に作られています。そのため合流には、中継の作り直しか、削除の取り消しが要ります。

ランチャーの候補（launcher_dirs）

ランチャーで「どのフォルダで開くか」の候補を、手動の登録と自動の走査で管理します。起動 15 秒後から 3 時間ごとに、git リポジトリの親、最近の作業フォルダ（ailog.db を読む）、会話の中の言及を走査します。候補は ~/.mycmux/launch-dirs.json に置かれます。

人が採用した候補は、launch-roots.txt に書き出されます。作者のスクリプトの旧版（update_launch_anken.py、update_launch_dev.py）のタスクは、9 月上旬から無効です。

ペインの整理（自動命名、ペイン整理、ペイン再配置）

機能起動判定送るもの
自動命名15 分ごとと、画面の変化から 90 秒後CLI（codex exec）画面の末尾 14 行、作業フォルダ
ペイン整理ボタンCLI画面の末尾 8 行、作業フォルダ

ペイン再配置（Jev）事前計算とボタンOpenRouter の Jev（typesafe/jev-1.13）秘密らしい文字列を伏せた、ペインの状態

Jev は TypeSafe 社の判定専用のモデルで、文章は作らず、質問に型のついた答え（選択肢の確率など）を返します。キーは Windows では DPAPI を使って jev-key.bin に保存し、設定、data.json、localStorage、ログには出しません。秘密らしい文字列を伏せる処理は Jev の経路にしかなく、CLI の判定の経路（命名、整理、再配置、次の一手）にはありません。

アプリが LLM を呼ぶ箇所（全件）

src-tauri/src/ai/mod.rs は、「設定 → CLI の起動コマンド」を組み立てるだけの層です。API キーは使わず、CLI のログイン（アカウント切替で差し替える認証）で動きます。Codex は codex exec --model <m> --ignore-user-config -c model_reasoning_effort=low -c features.fast_mode=false - で起動します。作者の ~/.codex/config.toml にある effort や MCP を持ち込まないためです。

現在の設定は、Codex の GPT-5.6 世代の軽量モデルです。作者のモデルの割り当て（~/.claude/references/model-routing-current.md）は、9 月下旬に 5.6 系をラダーから外しました。走査と分類の段（L0）は GPT-6 世代の軽量モデルになっていて、背景の判定に使うモデルだけが 1 世代古いままです。

ペット、壁紙、テーマ

  • ペットは表示オフ（pet_display_mode = none）。置き場は Codex の ~/.codex/pets で、ギャラリー（https://codex-pets.net/api/pets）から取得して展開する。画像の縁の補正は、アプリの src/lib/petKeyHalo.ts と作者のスクリプト pet_defringe.py が同じ目的で別々に実装している
  • 壁紙は縮小画像だけを同梱し、原本は必要なときに miyafcos/mycmux-team の Release から取得する
  • テーマは raimei

メール監視

アプリには実装がありません。あるのは仕様 v4（docs/mail-spec-260827.md）と ADR 0004〜0007 だけで、8 月末に観測の作戦の段 4 へ、9 月中旬に 1.x へ送られました。実装は、skill の ~/.claude/skills/unreplied-sweep/（9 月中旬から Mac が正本）とポケットが、それぞれ別に持っています。

diag、e2e、その他

  • diag（src-tauri/src/diag.rs）: ~/.mycmux/diag.log に 1 行ずつ書き、1MiB で diag.log.1 に回す。約 6 日分が、ほぼ PTY モニタの行で埋まっている。panic もここに書く（9 月中旬に 1 件）
  • e2e: テスト用の socket コマンド。出荷版には入らない
  • 端末設定の読み取り: 呼ばれてはいるが、使われるのは Windows のビルド番号だけ（エディタ本体）

作者の運用やエージェント製品との重なり（21 件）

  1. ~/.claude/.credentials.json を書くのが 3 者（アプリの切替、Claude Code 自身、claude-codex の ccproxy）
  2. Grok の auth.json を、使用量の取得が書き戻す
  3. 認証の平文の控えが、アプリ側に溜まる
  4. ターミナルで claude login したログインが、アプリのアカウント一覧に黙って増える
  5. 使用量の表示が 2 系統ある（アプリの API 取得と、作者の statusline）
  6. AI ログのアーカイブの持ち主が 2 者いる
  7. アプリの DB（ailog.db）を、作者のスクリプトが 4 時間ごとにバックアップする
  8. セッションの分析が 2 系統ある（AI ログと、個人の hook の session-summarize、日報、amadeus）
  9. 案件の割り当て規則が 2 つある（アプリの project_rules と、作者の運用の PROJECT_RULES）
  10. 過去の会話の検索が 2 つある（history.db は読む側なし、作者の運用は session-archive を検索）
  11. 背景の判定のモデルが 1 世代古い
  12. 価格表に新しいモデルがない
  13. 背景の判定がエージェント製品の保存先に会話を残し、それを AI ログが読み戻す
  14. セーブポイントと複製が、エージェント製品の会話の保存先に書く
  15. ランチャーが、claude-codex のモデル表（作者の運用のファイル）を読む
  16. launch-roots.txt を書くのが 2 者
  17. ペットの置き場が、Codex のフォルダ
  18. Jev のキーが 2 か所にある（製品は DPAPI、評価スクリプトは別ツールの .env）
  19. メール監視は、アプリに仕様だけがあり、実装は skill にある
  20. 使用量を、socket で skill やスクリプトに公開している
  21. ポケット本体がリポジトリの外にあり、socket を使う
