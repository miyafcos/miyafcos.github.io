mycmux とハーネスは、4 本の「橋」でつながっています。ハーネスとは、Claude Code、Codex、Grok の設定と、~/.claude にある skill、hook、スクリプトのことです。

  1. socket（アプリが localhost で受け付ける命令の口）と、それを包む CLI と bridge
  2. hook（エージェントが自分の状態を知らせる仕組み。アプリがハーネスの設定ファイルに書き込んで入れる）
  3. PTY に渡す環境変数
  4. 同梱スキルパック（アプリがハーネスのコードを配る）

4 本とも動いていますが、向きが両方にあります。アプリはハーネスの設定、認証、信頼の各ファイルを書き、ハーネスはリポジトリ作業ツリーの CLI を直接呼びます。版のずれや片側だけの変更が、もう片側を黙って壊す箇所が 20 か所ありました。

このページは、アプリとハーネスがどこで接していて、どちらが何を知っているかをまとめたものです。mycmux は最初はターミナルを並べるエディタでしたが、8 月以降、委譲便、判断カード、hook、アカウント切替などを取り込みました。その結果、アプリとハーネスの両方にまたがる仕組みが増えました。

このページの目的は、作者の見立てを確かめることです。見立ては「ハーネスで管理すべきことと、アプリとして管理すべきことの両方を抱えている」です。どの橋を何が渡っているかという形で確かめます。どちらに寄せるべきかの提案は、責務の分け方に書きます。

3 つの側と 4 本の橋

図の読み方です。矢印は書き込みや命令の向きです。② hook の矢印は、アプリがハーネスの設定ファイルに hook を登録する向きです。登録された hook からの申告（エージェントからアプリへ）は、① と同じ socket を通って届きます。

側中身主な置き場
アプリRust（Tauri）とフロント（React）。ワークスペース・タブ・ペイン、PTY、保存、観測、表示~\cmux-for-linux-dev-master、%APPDATA% の下のアプリのフォルダ、~/.mycmux/
ハーネスClaude Code・Codex・Grok の設定と、作者の skill・hook・スクリプト・台帳・規則~/.claude/、~/.codex/、~/.grok/、%USERPROFILE%\claude-ops\
橋両方にまたがる部品。socket と CLI・bridge、hook の helper、環境変数の約束、スキルパックscripts/mycmux_agent_cli.py、~/.mycmux/hooks/v1/mycmux_hook.py、skills/claude/

橋 1: socket（命令の口）

socket は 127.0.0.1 の TCP 1 本で、1 行に 1 つの JSON で命令を送ります。ポート番号は ~/.mycmux/mycmux.port、合言葉（token）は ~/.mycmux/mycmux.token にあり、どちらもアプリの起動ごとに作り直されます。loopback 以外からの接続は捨てます（src-tauri/src/socket.rs:1036-1089）。

合言葉は 2 種類あり、受け付ける範囲（realm）を分けています。

範囲合言葉使える命令使う者
一般（broad realm）起動ごとの token hook 以外のすべてCLI・bridge・pocket・2 個目の mycmux
hook（hook realm）エージェント起動ごとの使い捨て合言葉 hook_cap hook.health・hook.observe だけhook の helper

両方の合言葉を持つ要求は拒否し、一般の範囲から hook.* は呼べません（src-tauri/src/socket.rs:180-208）。

命令は、Rust が直接答えるものが 8 系統、フロントへ転送して答えるものが 47 名（正式名 39、旧名 8）です。

系統主な命令答える側主な呼び手
hook hook.health・hook.observe Rust hook の helper
状態session.state_view（ペインの状態の一覧）・status.subscribe（変化の購読）Rust CLI の status・bridge・pocket
合言葉の発行launch.issue_hook_cap Rustランチャーのシェル関数
開くapp.open_paths・app.activate（リポジトリの最新の版で追加）Rust 2 個目に起動した mycmux
ワークスペースworkspace.list・workspace.new・workspace.closeフロントCLI
ペインpane.list_all・pane.spawn_tab・pane.send_text・pane.read・pane.close_tab ほかフロントCLI・bridge・pocket・ハーネスの委譲
Web ペインweb.open・web.read・web.push ほか 19フロントoracmux
使用量account.usageフロントCLI・ハーネスの birdseye

フロントで答える命令は、主窓（リーダー窓）だけが実行し、30 秒で応答しなければ打ち切ります。同じ処理関数 handleSocketCommand を、アプリの画面自身も内部の API として 6 か所で呼んでいます。入力欄、返信欄、ペイン整理、WorkOrder などです。外向きの約束を変えると、画面の挙動も一緒に変わります。

socket には、稼働中の exe の版や、使える命令の一覧を問い合わせる命令がありません。ハーネスはリポジトリ作業ツリーの CLI（HEAD、調査時点の最新の版）を使い、稼働していた exe は 1 つ前の版でした。そのため、新しい命令は要求が失敗して初めて分かります。たとえば spawn --target omp は、稼働していた版では通らないはずです（推測）。

CLI mycmux_agent_cli.py

scripts/mycmux_agent_cli.py は、socket の命令を 1 つずつ送る薄いクライアントです。ハーネスの委譲は、ここを通って子のペインを立てます。

サブコマンド送る命令既定と約束
spawn --target <種類> pane.spawn_tab呼び出し元と同じタブにペインを足し、裏で起動する。--split を付けたときだけ新しいタブを割る。--workspace などを --split なしで付けるとエラー
spawn-tab pane.spawn_tab起動する種類（--target）かコマンド（-- 以降）のどちらか一方
send --session pane.send_text --text だけは未確認の書き込み。--enter は Enter を最大 3 回押し直す。--key enter は 1 回
read、close-tab、rename、move pane.read ほか宛先はペインの PTY セッション ID
status session.state_view応答を厳しく検査する
workspace-new、workspace-close workspace.new、workspace.close前面のワークスペースは閉じられない
web-* web.* Web ペインの操作

--target で選べるのは 9 つです。claude、codex、claude-codex、grok、agy、hermes、omp、shell、web があります。

CLI の status（全件）は、いま必ず失敗します。閉じたペイン 88〜90 件の入力改訂番号が null で、CLI は非負の整数を要求するためです（scripts/mycmux_agent_cli.py:885 と src-tauri/src/socket.rs:789-791）。bridge は null を許しているので落ちません。

pocket には、CLI と同じ厳しい検査が移植されています。また --model と --effort は、prompt、handoff、resume と一緒に渡すと、エラーも警告も出さずに捨てられます（scripts/mycmux_agent_cli.py:471-475）。

橋 2: hook と使い捨ての合言葉

hook は、エージェントが「質問を出した」「ターンを終えた」などを自分で知らせる仕組みです（意味づけは観測とカード）。アプリは起動のたびに次のファイルを書き換えます。

書く先中身
~/.mycmux/hooks/v1/mycmux_hook.py helper 本体（exe に埋め込んだものを書き出す）
~/.claude/settings.json Claude の 7 イベント（UserPromptSubmit・PermissionRequest・Notification・PreToolUse・PostToolUse・Stop・SessionEnd）に helper を登録
~/.codex/hooks.json Codex の 4 イベント。~/.codex/config.toml の信頼の印（trusted_hash）を照合し、未承認なら Codex だけ使わない
~/.grok/config.toml Grok の 5 イベントを、印のコメントで囲んだブロックとして末尾に置く

この導入には、画面から止める手段がありません（~/.mycmux/agent-hooks-state.json が無ければ常に導入）。

  1. ランチャーで起動
  2. 合言葉を発行
  3. 子プロセスだけに渡す
  4. helper が申告
  5. 関所で照合

エージェントの起動ごとに、ランチャーのシェル関数（claude、codex、grok などをかぶせたもの）が socket の launch.issue_hook_cap を呼びます。使い捨ての合言葉を受け取り、その 1 回の起動にだけ環境変数 MYCMUX_HOOK_CAP で渡します（src-tauri/src/launcher.sh:88-128）。helper は、合言葉が無ければ何もせずに終わります。

合言葉を配るのはランチャーのシェル関数だけで、Rust はこの変数を消すだけです。再起動後の復元のように、アプリがランチャーを通さずにエージェントを直接起動する経路があります。この経路では hook が何もせずに終わる、とコードからは読めます（実機では未確認）。ADR 0009 が想定した注入の位置（Rust の起動処理）とも違います。

hook の導入で見つかった問題は、次の 4 つです。

  1. Grok の 5 重登録。~/.grok/config.toml に mycmux の hook が 5 組（25 行）入っています。Grok が設定を書き直すと印のコメントが消えます。アプリは印でしか自分の分を見分けないため、起動のたびに 1 組ずつ増えます
  2. ハーネスの正本を書く。作者のホームの CLAUDE.md は、settings.json の hooks を「慎重に扱う」対象にしています。一方でアプリは、差分があれば毎回書き換えます（同時の編集は照合して拒否する作り）
  3. helper の改行。リポジトリは LF、書き出された helper は CRLF です。別の checkout からビルドした exe を交互に起動すると、毎回書き直されます
  4. テスト機。テストプロファイルでは導入しませんが、live の設定が指す helper は MYCMUX_RUNTIME_DIR を読みます。そのため、テスト機の中のエージェントの申告は、テスト機の socket に届きます

橋 3: PTY に渡す環境変数

アプリは PTY（ペインの中の疑似端末）に、自分のペインの ID や成果物の置き場などを環境変数で渡します。同時に、一度きりの指示（resume、引き継ぎ、起動対象）が別のペインや次の起動へ漏れないように、4 か所で消しています。これは 5 月の版で起きた事故の再発防止です。Ctrl+P の環境変数が他の PTY へ漏れ、新しいペインが勝手に resume されました（CHANGELOG.md:2046-2052）。

場所いつ何を消すか
src-tauri/src/lib.rs:305-330 exe の起動時、自分の環境から20 キー
src/lib/spawnLaunchEnv.ts:3-35新しいペインを作るとき、親ペインの環境から20 キー
src/components/layout/SocketListener.tsx:1078-1101 data.json に保存する前18 キー
src-tauri/src/commands/terminal.rs:680-755（sanitize_launch_env）PTY の起動直前17 キー。resume は ID と種類が揃うとき、引き継ぎは種類と元のペインが揃うときだけ残す

消したあと、アプリが正しい値を入れ直します（MYCMUX_PANE_SESSION_ID、MYCMUX_RUNTIME_DIR、MYCMUX_TAB_ID、成果物の出力先など）。4 か所は同じ文字列の並びを 4 回書き、契約テスト tests/test_ephemeral_env_keys_contract.py で揃えています。リポジトリの CLAUDE.md は「3 層」と書いていますが、いまは 4 か所です。

ハーネスも、この環境変数を読みます。ask-inject.py と子の質問封じの hook（dispatch-child-guard.py）は、MYCMUX_PANE_SESSION_ID と委譲の台帳で「自分は子か」を決めます。アプリがこの変数の付け方を変えると、ハーネスの判断が黙って変わります。

橋 4: 同梱スキルパック

アプリは 3 つの skill と CLI を、exe に埋め込んでいます。skill は、session-dispatch、mycmux-bridge、oracmux です。ほかの PC の ~/.claude/skills/ と ~/.mycmux/bin/ に入れられるようにするためです（「設定 → AI → Claude Code スキル」）。ハーネスのコードを、アプリのリリースが配っている形です。

  1. 保守者が python scripts/sync_claude_skills.py --from-live --write-manifest で、live の skill を持ち運べる形（個人のパスを置き換えたもの）に変換し、リポジトリに入れる
  2. ビルドで exe に埋め込む（src-tauri/build.rs:40-80）
  3. 利用者が設定画面から導入する

調査時点で、パックと live は一致していました（--check は exit 0）。ただし調査した PC は保守者の機で、live が原本なので導入の印がありません。設定画面は 3 つとも「ローカルで改変済み」と表示します。

ここで「退避して置き換える」を押すと、原本が持ち運び版に置き換わります（押してはいけない、コードからの推論）。~/.mycmux/bin/mycmux_agent_cli.py は 9 月中旬の版のままで、誰も参照していません。

ハーネス側の hook の一覧

Claude の hook は、10 イベントに 22 個が登録されています。表の中の印は次のとおりです。

  • 「（mycmux）」は、アプリが入れた mycmux の hook です
  • 「（mycmux 前提）」は、ハーネスが mycmux を前提に動くものです
  • 「（二重記録）」は、アプリと同じ出来事を別に記録しているものです
イベント呼ぶもの目的
UserPromptSubmit hooks_dispatch.py から prompt-secret-guard、rule-drift-guard、session-inject（mycmux 前提）、ask-inject（mycmux 前提）、ターンの記録（二重記録）秘密の遮断、文脈の注入、判断カードの注入
UserPromptSubmit feedback-injector、skill-hint-injector、turn_active（mycmux）feedback と skill の候補、ターン開始の申告
PreToolUse risk-guard、agent-model-guard、comms-search-guard、dispatch-child-guard（mycmux 前提）、pre_tool_use（mycmux）危険な操作の拒否、子の質問封じ、ツール使用の申告
PostToolUse checkpoint、slack-log、skill_usage、turn_active（mycmux、AskUserQuestion の後）途中経過の保存、使用記録

Codex の hook は、SessionStart（通知）と Stop（使用量の収集）が自前です。残り 4 つは mycmux のものです。Grok の hook は mycmux のものだけです。

Codex の Stop が切り離して起動する ~/.claude/scripts/ai-usage-collector.py は、実在しません（~\.codex\hooks\scripts\hooks_dispatch.py:12 と :88、調査当日に作業の会話で確認）。Codex のターンが終わるたびに、使用量の収集が黙って失敗しているはずです（失敗の記録は確かめていない）。

bridge の安全な送信

mycmux-bridge（ハーネスの skill）は、別のペインに取り違えや二重送信なしで入力するための道具です。委譲便の追加指示（dispatch_send.py）も、これを使います。

  1. 宛先を解決し、session.state_view で、生きているか、期待した注意の印かを確かめる
  2. 画面を読んで指紋を取り、状態と画面をもう一度取り直す。変わっていたら何も書かない
  3. 本文を、期待値 4 点（epoch、attention id、セッション改訂番号、入力改訂番号）付きで書く。Rust が事前に照合し、最後に write_to_session_guarded がすべてを照合してから書く
  4. 入力欄に本文が見えるまで待ち、状態と画面を確かめ直してから、Enter を 1 回だけ送る
  5. 入力欄から本文が消え、画面か状態が変われば「届いた（observed_delivered）」とする

送信の安全は、3 者に分かれて持たれています。CLI（Enter を最大 3 回）、bridge（1 回）、アプリの入力欄（押し直さない）です。bridge は、リポジトリ作業ツリーの CLI をモジュールとして読み込みます。そのため、別のセッションが未コミットで CLI を編集すると、それがすぐハーネスに効きます。

知っていることの非対称

アプリだけが知っていること

ハーネスは、socket で聞くしかありません。
