エージェントとの作業

別のエージェントへ任せ、複数の会話をまとめて見て、止まったら気づき、作業を残して戻るまでの操作です。エージェントの起動のしかたは画面と操作に、テーマやキーの変更、使用量の確認はアカウントと設定にあります。

別のエージェントへ任せたい

作業を別のエージェントへ渡すことを委譲と呼びます。相手を可視ペイン（画面上で見えるペイン）で起動し、途中で人が会話に入れる形にします。

最初に用意するもの

このページのコマンド例には、Python 3 と公開リポジトリを手元に用意します。委譲 CLI は公開リポジトリの scripts/mycmux_agent_cli.py です。「設定 → AI → Claude Code スキル」から導入する方法もあります。エージェント側のルールにも、可視ペインで委譲する方針と CLI の場所を書いておきます。

エージェントが mycmux の中にいるかは、環境変数 MYCMUX_TERM_PROGRAM が mycmux かどうかで判定できます。自分のペインとそのセッション ID は MYCMUX_TAB_ID と MYCMUX_PANE_SESSION_ID で分かります。

環境変数の全一覧は、README（付録 F）にあります。

エージェントは、Web ペインを裏で開く、読む、操作する作業もできます。

ページを開く、読み込みを待つ、要素を探して押す、文字を打つ、ファイルを添える、画面を撮る、閉じる、といった操作を委譲 CLI から使えます。

Windows では、実際のクリックやキー入力と同じ扱いの操作もできます。

Web ペインには印が付き、そこでの会話もダッシュボードの一覧に出ます。

環境変数エージェントが確認できるもの
MYCMUX_MARKDOWN_OUT Markdown の成果物の出力先
MYCMUX_HTML_OUT HTML の成果物の出力先
MYCMUX_ARTIFACTS_DIRそのセッションの成果物フォルダ

引き継ぎ書を渡す

mycmux 内で、取得したリポジトリのルートから実行する例です。先に task.md へ、目的、変更してよい範囲、完了条件を書いておきます。

python scripts/mycmux_agent_cli.py spawn --target codex --prompt-file task.md

呼び出し元のタブに、新しいペインが裏ペインとして開きます。いま操作しているペインは移動しません。

spawn の起動方法は 4 つあり、同時には 1 つだけ指定します。

指定起動のしかた
--prompt か --prompt-file指示書を読ませて始めます。
--handoff-from-session既存の会話の履歴から引き継ぎ書を作って渡します。
--resume-sessionセッション ID を指定して、その会話を再開します。
指定なし新規に起動します。
オプション起動先や動作
指定なし呼び出し元のタブに裏ペインを作り、フォーカスを移しません。
--split新しいタブを作ります。
--workspace分割先のワークスペースを ID で指定します。--split が必要です。
--anchor-pane分割の基準となるタブを指定します。--split が必要です。
--direction right右に分割します。--direction down なら下です。--split と組み合わせます。
--cwd、--label作業フォルダとペインの表示名を指定します。
--no-activate起動先へフォーカスしないことを明示します。
--activate起動先の選択を求めます。別のワークスペース自体は前面へ移しません。
--model、--effortランチャーで選ぶのと同じモデルと effort を渡します。

--model と --effort は、ランチャーの選択と同じ経路を通ります。指定しなければ CLI の既定で起動します。

旗と読める値など、渡せない値は黙って捨てずに拒否して返します。

--target に指定できるのは claude、codex、claude-codex、grok、agy、hermes と、shell、web です。

--prompt などで会話を継ぐ指定は、mycmux が会話を追える相手にだけ渡せます。agy と Hermes は会話ファイルを持たないため、対象になりません。

mycmux 内の親タブを特定できなければ、別タブに勝手に変更せずエラーで止まります。

右のタブに置くなら、次のように指定します。下の画面も、右のタブを使った配置です。

python scripts/mycmux_agent_cli.py spawn --target codex --prompt-file task.md --split --direction right --no-activate

ほかのサブコマンド

同じ CLI には、起動以外のサブコマンドもあります。委譲先の画面を読む、追加の指示を送る、といった操作に使います。

サブコマンド用途
workspaces、panesワークスペースとタブの一覧を出します。send と read に使う ID の確認用です。
statusセッションの状態を読みます。
read端末の末尾を読みます（既定 80 行、最大 400 行）。
send動いている端末へ文字列やキーを送ります。
rename、close-tabペインの名前を変える、ペインを閉じる操作です。

send は生の端末入力です。宛先を間違えると別の作業を壊すため、先に panes で ID を確かめます。--enter を付けたときは、届いたことを確認できた場合だけ成功として返します。

全オプションと全一覧は、README（付録 C）にあります。

別のワークスペースを先に作る場合は、workspace-new --name review を実行します。返った workspaceId を、spawn --split --workspace の値に渡します。

新しく作ったワークスペースへ最初のエージェントを起動すると、そこに出ている未使用の起動メニューが置き換わります。空のメニューだけのペインは残りません。

使い終わったワークスペースは workspace-close --workspace <id> で閉じます。表示中の画面は動かないので、人が見ている作業を邪魔しません。

表示中のワークスペースは閉じられず、拒否されます。閉じたワークスペースにある端末は終了します。

send で本文だけを渡した場合、送信の確定まで済んだとは限りません。--enter や --key の結果は、到達を確認できたかまで調べます。read は端末の表示を返すもので、会話の全履歴ではありません。裏ペインも読み取れますが、最大 400 行の範囲です。

終わったかを確かめる

確認するもの分かること
指示書で場所を決めた完了マーカー相手が完了を報告したか。
対象セッションのログの増分作業や会話が進んでいるか。
編集ファイルの更新時刻と内容成果物に実際の変更があるか。

「保存しました」という返事だけでは、終わりにしません。指定した成果物とテスト結果まで照合します。実務での流れは、引き継ぎ書つきで任せる例にあります。

複数の会話をまとめて見たい

ダッシュボードは、全ワークスペースのセッションを一覧で見る画面です。Ctrl+Shift+G で開き、Esc で戻ります。セッションは、ひとつのエージェントと続ける会話の単位です。

上の「委譲の見守り」には、動作状態、最終チェック、次回の確認予定が出ます。「セッションへ戻る」か Esc で、元の作業へ戻れます。

一覧と計器行

左の一覧は「要回答」「要確認」「作業中」「その他」に分かれます。各行の下の計器行には、モデル、コンテキスト占有率、概算コスト、ID が並びます。コンテキスト占有率は、会話で使える文脈の枠をどれだけ使ったかの目安です。

一覧の区分主な状態
「要回答」質問や承認への返答が必要です。
「要確認」未読の完了やエラーなど、確認することがあります。
「作業中」作業を続けているセッションです。
「その他」上の区分に入らない状態です。

計器行には、モデルと effort、CTX の割合、概算コスト、会話 ID の先頭部分が出ます。検索では、ワークスペース名、ラベル、作業フォルダ、ログの内容を探せます。行をダブルクリックすると、そのセッションの元の画面へ戻ります。

最後の出力から 60 秒を過ぎたセッションは、プロセスが残っていても待機扱いです。入力待ちや完了が明示されている場合は、その状態を保ちます。

会話列と宛先

一覧の行をクリックすると、中央に会話列（会話ごとの縦の列）が開きます。同時に並べる列数は、入力欄の上の 1〜5 で選べます。残したい列は「固定」で留めます。

入力欄で @ を打つと、送る相手の候補が出ます。宛先は複数でも構いません。送信後は宛先ごとの結果を確認でき、失敗した分だけ再送できます。

会話列の「▲」「▼」で、送った指示を前後にたどれます。ツールの実行は、折り畳まれた見出しを開いて確認します。会話の記録を取得できない場合は、端末から拾える情報を表示します。

  1. 下の「入力先:」を見て、送る相手を確かめます。
  2. 「ここに指示をタイプ」に本文を書きます。
  3. Enter か「送信 ⏎」で送ります。
  4. 宛先ごとの結果を見て、確認できなかった分を調べます。

改行は Shift+Enter です。送れたか不明な相手へ、自動で同じ指示を送り直すことはしません。

質問カードと次の一手

Claude Code の質問は質問カードに出て、選択肢から答えられます。複数選択のときは、選んだ後に「送信」で確定します。質問が変わっていたり、別の入力が割り込んだりしたときは送信を止めます。

質問が来ると、画面の上に「質問」の帯が出て、左一覧の「要回答」に分類されます。会話列の下に質問カードが開き、「その他 (自由入力)…」から文章でも答えられます。下の画像は、カードの部分を拡大しています。回答待ちの間は、通常の返信を先に送りません。

「次の一手」は、選んだ会話に返す行動の候補です。候補を押すと「送る全文」を確かめてから送れます。

候補は最大 3 つです。内容を見直したいときは、候補を更新してから全文を確かめます。

次の一手には、状態から決まる定型の候補が先に出ます。AI の具体案は後から足すため、画面を開くだけでは AI を起動しません。

報告インボックスと気づきカード

報告インボックスは、対応が必要な気づきカードをまとめて見る入口です。気づきカードは「回答待ち」「停止を検知」などの気づきが優先度順に並び、理由と根拠、次の操作つきです。

入力文と宛先から目的、素材、完了条件を組み立てる「実行契約カード」もあります。「GO」を押すまで、プロセスもブランチも作りません。

実行契約カードでは、目的、素材、書き込み先、完了条件を確かめます。素材に未取得や失敗があれば、「GO」を押して進めることはできません。参加するセッションの役割は、次の 4 つから選びます。

役割担当すること
素材作業に使う情報を出します
作業個々の作業を進めます
統合役結果をまとめます
レビュー結果を確認します

開始後は、次の順で進みます。

  1. 素材を取り込みます。
  2. 統合用のセッションでまとめます。
  3. 統合テストを行います。
  4. 人が承認した後、本ブランチへ反映します。

配置図

右の配置図には、ワークスペース、タブ、ペインの実際の並びが出ます。チップをクリックすると会話列が開き、ダブルクリックで元の画面へ移ります。複数のペインを選んで「選択を閉じる」を押すと、対象を確認してからまとめて閉じられます。

まだ起動していないセッションは、点線ペインとして席だけ用意しておけます。

点線ペインを押して起動する操作は封印中で、現行版では使えません。増えたペインは、配置図の下の「ペイン掃除」か Ctrl+Shift+K で片づけます。終了済みのペインをまとめて閉じ、直後なら「取り消し」で戻せます。

未送信の入力があるペイン、直近 5 分に出力があるペイン、表示中のペインは、掃除から保護します。判定に失敗した場合は閉じません。閉じたペインは Ctrl+Shift+T でも戻せます。

配置図のチップには、種類、状態、返答待ち、CTX、最終出力からの時間が出ます。範囲をドラッグするか、Ctrl や Shift を押しながら選ぶと、複数を選択できます。

掃除の「内訳」では、終了済み、入力待ちの候補、ロック中の一覧を見られます。チェックで対象を選び、閉じる範囲を確かめます。

過去の作業を根拠つきで探す

全セッション履歴の検索は、会話ごとの読み書き、実行、テスト結果を追記専用の記録に貯め、全文検索します。索引の作成に AI は呼びません。結果には必ず根拠が添えられます。

返事待ちや停止に気づきたい

通知の入口、委譲の見守り、レート制限の扱い、短い知らせの 4 つです。

待機バッジから移る

ペインとサイドバーの待機バッジで、人が関わらないと進まない状態に気づけます。該当するワークスペースとペインを選んで移ります。全ワークスペースの状態は、ダッシュボードでまとめて確かめます。

通知と通知サウンドは「設定 → 通知とレイアウト」で切り替えます。承認待ちの画面やレート制限が、検知の対象です。通知サウンドが有効なら、入力待ちの検知時に短いチャイムが鳴ります。対応が必要なペインへは、Ctrl+Alt+A で直接移れます。

サイドバーのキャラクターにも、作業の状態が出ます。承認や質問では呼ぶ姿、エラーや枠切れでは困る姿、作業中は走る姿です。ターンが終わって未読なら知らせる姿、待機中なら寝る姿になります。待機バッジと合わせて、開く会話を選ぶ目印にできます。

承認の画面が 2 回続けて検出されなくなると、承認待ちを解除します。

見守りと無応答の検知

委譲の見守りは、同じ状態を 2 回続けて検知してから通知します。ダッシュボードには最終チェック時刻と、停止していればその理由が出ます。出力が少ないというだけでは、停止とは判定しません。

巡回で見つけた状態のうち、右下に知らせるのは人の操作が要る 3 種類だけです。判断を待っている、作業が検収で不合格になった、送信されていない入力が残っている、の 3 つです。知らせは「開発 の「調査レーン」が判断を待っています」のようにワークスペース名とペイン名で出て、「開く」でそのペインへ移ります。残りの状態はダッシュボードで確かめます。

標準の確認間隔は 10 分です。通知が多すぎる場合は、設定の「通知の敏感さ」で「控えめ」を選べます。見守りが停止中や未計測なら、帯に出る理由を確認します。

レート制限と休眠

レート制限で止まったペインは「停止」ではなく「レート制限で待機中」として扱い、休眠処理の対象から外します。休眠したセッションを片づける時間は、「設定 → 自動化」で 30 分後などから選べます。

トーストとエラー帯

短い知らせの置き場は、画面右下のトーストです。画面の一部が止まったときは、その部分だけエラー帯に変わり、「再試行」で戻せます。重ねて開いた画面は、Esc か背景のクリックで閉じます。

作業を残して戻りたい

作業を残す手段は 3 つです。再起動時の自動復元、区切りで作るセーブポイント、別の PC へ渡す受け渡しファイルを、時間の順に並べます。

自動復元と、閉じたペインの復活

再起動すると、ワークスペースやタブの構成、作業フォルダ、直前の会話表示が戻ります。タブの復元には未解決の不安定さがあるため、区切りではセーブポイントも残しておきます。

どのペインがどの会話に対応するかは、記録から決めます。「いちばん新しいファイル」から推測して結び付けることはしません。対応を確認できない場合は、復元を止めて警告を出します。

誤って閉じたタブやペインは、Ctrl+Shift+T で開き直せます。

閉じた記録は、直近 5 件から戻せます。「セッションを複製」は元の会話を残して別の会話を作り、失敗時は引き継ぎ方式で開きます。

主ウィンドウの位置、サイズ、最大化の状態も復元します。

過去の会話を選ぶ

Ctrl+P の Resume で会話を検索し、右に分割して再開します。対象は Claude Code、Codex、claude-codex の 3 つです。Grok Build の会話は、この一覧には出ません。

Resume は外部のセッション履歴ツール crsm を使います。Rust のビルド環境を用意し、crsm の公開リポジトリを取得して、手元で次を実行します。できた実行ファイルを PATH の通った場所に置きます。

git clone https://github.com/miyafcos/crsm.git
cd crsm
cargo build --release

Resume では、ラベル、本文の抜粋、作業フォルダ、会話 ID で検索できます。最初は現在の作業フォルダに絞られています。

要約だけ残っていて会話ファイルがない場合は、最初の確定で警告が出ます。再度確定すると、新しい会話として始めます。

セーブポイントから再開する

セーブポイントは、要約、引き継ぎ書、復元情報をまとめたローカルの記録です。タブのペインバーにある「セーブポイントを作成」で残します。一覧の入口は、タイトルバーの「セーブポイントを開く」です。

  1. 「記録の見出し」を入力します。空欄なら最後の指示から付けます。
  2. 初回は「ここまでを保存」、更新なら「保存内容を更新」を押します。
  3. 終了時の区切りは「終了時の記録を残す」で残します。
  4. 作業画面を残したい場合は、閉じない選択を確かめます。

保存するのは、この PC にある Claude Code と Codex のログです。作業途中の記録は更新できますが、終了時の記録はその区切りのまま残ります。会話がまだない場合は、1 往復してから保存してください。

一覧の上部に「受け取る」「更新」、その下に「保存済み」「ゴミ箱」があります。下の一覧には、見出しと状態のチップが付いた記録カードが 1 件あります。

選ぶ操作再開のしかた
「Claude Codeへ渡す」「Codexへ渡す」引き継ぎ書を読んだ新しい会話を、右に開きます。
「会話ごと続ける」会話履歴ごと、元の会話から派生したセッションとして再開します。
「人に渡す」1 件を .mycmux-transfer ファイルに書き出します。

引き継いだエージェントは前提と次の案を整理し、指示を待ちます。記録は最終更新から 48 時間でローカルのゴミ箱へ移るため、残したいものはピン留めします。

別の PC では「受け取る」を選ぶか、ファイルをアプリへドロップして取り込みます。受け渡しファイルに作業フォルダは含まれません。作業ファイルは、別に用意します。

カードを左右へドラッグすると完全再開、下へドラッグすると現在の会話への引き継ぎを選べます。動いているエージェントへファイルを落とすと、引き継ぎ文が入力欄に入ります。その時点では送信せず、人が内容を確認して確定します。

ゴミ箱の記録は戻せます。完全に消す場合は、確認を経て削除します。受け取り先に同じ作業フォルダがない場合は警告が出るため、実ファイルの場所を確認します。

同じ受け渡しファイルをもう一度取り込んでも、記録は重複しません。

ファイルの保存先

設定や記録は ~/.mycmux/ に置かれ、--profile を付けた起動（テストプロファイル）では ~/.mycmux-<name>/ に分かれます。セッションの成果物は ~/.mycmux/sessions/ の下です。30 日を過ぎたセッションは ~/.mycmux/sessions-trash/ へ退避されます。

保存先の全一覧は、README（付録 G）にあります。

~/.mycmux/ の下中身
launch-dirs.jsonランチャーの登録フォルダです。
sessions/セッションごとの成果物です。
diag.log起動や不具合の診断ログです。
ailog.db AI ログ分析の索引です。

保存先を調べるときは、普段の起動かテストプロファイルかを先に確認します。
