作業場所を分けたい

案件や調査ごとに分ける作業場がワークスペースです。その中に並ぶ端末の区画をタブ、区画の中で切り替える単位をペインと呼びます。

サイドバーの行には、ワークスペース名、ペイン数、ペイン名、キャラクターが出ます。

「⋮」を開くと、次の操作を選べます。

項目できること
「色」ワークスペースの目印の色を選びます。
「名前を変更」一覧に出る名前を変えます。
「新しいウィンドウで開く」作業を動かしたまま、ワークスペースごと別の窓へ移します。

色は 8 色と色なしから選び、行をドラッグすると並び順が変わります。サイドバーの幅は、境界をドラッグして 200〜560px に変えられます。

したいこと操作
ワークスペースを増やすCtrl+Shift+N を押すと、現在のフォルダを引き継いですぐ作ります。
レイアウトを選んで作るCtrl+Shift+Alt+N
ワークスペースを切り替えるCtrl+Tab で次へ。名前はサイドバーの行をダブルクリックして変えます。
右や下に分割するCtrl+Alt+D で右に分割します。Shift も押すと下に分割します。
同じ区画で切り替えるペインバーの「＋」で足します。裏のペインでもプロセスは動き続けます。
ペインを別のタブへ移すペインをつかんでドラッグします。落とせる先の枠が出ます。

タブの境界はドラッグで動かせます。ひとつに集中するときは Ctrl+Shift+Enter で拡大し、同じキーで戻します。ワークスペースごと別のウィンドウへ出したいときは、サイドバーの行の「⋮」から「新しいウィンドウで開く」を選んでください。セッションは起動し直さず、動いたまま移ります。

ペインを分析して並べ替える「ペイン再配置」では、案を確認しながら配置を決めます。待ち時間や失敗時の扱いは、ペインをまとめ直すで説明します。

別ウィンドウの × を押すと、確認のうえ、その窓のペインを終了して閉じます。ほかの窓が残っているときは、その窓の中身は次に起動しても戻りません。主ウィンドウへ戻すときは、閉じずに、窓の帯をつかんで主ウィンドウへ重ねます。

再起動後の窓の割り当ては引き継がれません。ペインを 1 つだけ窓にする操作は別で、閉じ方も違います（ペインを窓に切り離す）。

最後の 1 タブは閉じられません。動作中のペインを含むタブを閉じるときは、確認が出ます。

作成時のレイアウトは、1×1、2×1、3×1、4×1、2×2、3×2、1×2、2×3 の 8 種類です。既定は 3×1 です。切り替えて戻ると、そのワークスペースで最後に使ったペインへフォーカスが戻ります。

Ctrl を押しながら 1〜8 の数字キーを押すと、対応するワークスペースへ移ります。Ctrl を押しながら 9 を押すと、最後のワークスペースへ移ります。

境界線は、手で動かしたものだけが位置を覚えます。動かしていない線は、分割したときや閉じたときに均等へそろい直します。

分割は、そのタブが入っている区間の中だけで起こるので、手で広げた別のタブの幅は変わりません。

境界線をダブルクリックすると、その並びの覚えた位置を全部忘れて均等に戻せます。

ペインをドラッグすると、移動先を示す枠が出ます。タブのペインに追加する、タブを統合する、上下左右へ置く、新しいワークスペースへ移す、の違いを印で確かめます。生きているエージェントの上では、移動の代わりに引き継ぎ書を渡す印が出ます。

ペインをまとめ直す

「ペイン再配置」は、有効な案があれば 1 回の AI 分析で表示します。すべての案が無効だったときだけ、理由を添えて 1 回やり直します。

新しいワークスペース名が既存名と重なった場合は、連番を付けて案を残します。変わった名前は、案の警告で確認してください。

分析が失敗しても、表示済みの案と編集中の内容は残ります。失敗した理由は案ごとに表示し、応答全文は折り畳んであります。編集中に AI の案が完成したら、「AI案に切り替える」で再生成せずに確認できます。

設定で Jev を有効にすると、OpenRouter 経由でペインの関係を調べます。使い始める手順は、ペイン再配置に Jev を使うにあります。

関係は、同じ案件、関連する案件、無関係、情報不足の 4 つに分けます。案件別、役割別、現在の位置を生かす 3 案から選び、親子の作業は同じグループに保ちます。

確信度が低い分類や情報の足りないペインは、無理にまとめず保留します。同じ製品の実装と独立したレビューは、作業フォルダが別でも同じ案件として扱います。起動案内は、人の判断待ちと混同しないように判定します。

空のシェルは現在の位置に残し、関係を調べ直しません。広い既存配置からの再配置でも、新しい配置の上限を守って案を作ります。

適用中はプレビューを固定し、適用後に移動先を表示します。「元に戻す」はアプリ共通の下部に残るので、配置を確かめてから戻せます。

API の混雑やタイムアウトでは、失敗した通信だけを最大 1 回やり直します。認証、残高、応答形式のエラーは再試行しません。再試行中も、取り消しと処理の時間制限は有効です。

ペインを窓に切り離す

ペインをウィンドウの外へドラッグすると、そのペインだけが入った窓になります。窓にはサイドバーもタイトルバーもなく、上端の細い帯と中身だけが出ます。セッションは起動し直さないので、動いているエージェントは止まりません。

ターミナルのほか、HTML、Office、PDF、Web のペインも同じ操作で切り離せます。

帯をつかんでウィンドウ内のペインバーへ運ぶと、差し込み位置の印が出ます。その位置で離すと、ペインとして戻ります。

運ぶのをやめるときは Esc を押します。帯の「×」は、そのペインを閉じます。

落とす場所戻り方
ペインバーの差し込み位置その位置へペインを入れます。
タブの中央そのタブのペインに加えます。
タブの端分割して並べます。
サイドバーの新規作成部分新しいワークスペースとして置きます。

受け皿だけの窓がほしいときは、サイドバーの「新しいウィンドウ」から開きます。

切り離したペインは、元の窓だけでなく、サイドバーのある別の窓へも入れられます。

Windows では、切り離した窓が OS のスナップに乗ります。

macOS では標準の枠を持つ窓として開くので、窓を整えるアプリからも掴めます。

切り離していた窓は、次に mycmux を起動したとき同じ位置に戻ります。

窓を閉じると、その窓にある作業を終了します。ワークスペースごと別の窓へ出したときとは違い、閉じても主ウィンドウへは戻りません。移す操作と閉じる操作を区別してください。

タイトルバーのボタン

ウィンドウ上部のタイトルバーには、画面をまたいで使うボタンが並びます。左から、サイドバーの開閉、セーブポイント一覧、ワークスペース作成、詳しく設定して作るボタンです。右側に、「アカウントと使用量」「AIログ分析」「ダッシュボード」「設定」があります。

表示できること
「Toggle Sidebar」サイドバーを開閉します。キーは Ctrl+B です。
「セーブポイントを開く」保存済みのセーブポイント一覧を開きます。
「New Workspace」現在のフォルダを引き継いで、ワークスペースをすぐ作ります。
「エージェントとモデルを選んで新しいワークスペース」エージェントやレイアウトを選んで作ります。
「アカウントと使用量」使用量メーターの常時表示と、アカウント一覧の開閉です。
「AIログ分析」「ダッシュボード」「設定」それぞれの画面を開きます。
使用量の帯対象
「CC」Claude Code
「CX」Codex
「GK」Grok Build

取得できた枠の使用率は帯に出て、詳細はマウスを重ねると開きます。幅が狭くなると表示が縮まります。

Windows の右端には「最小化」「最大化」「閉じる」が並びます。最大化中は「元のサイズに戻す」で戻せます。

ペインが増えたとき

ペイン名をダブルクリックすると名前を変えられ、空欄で確定すると自動命名へ戻ります。Ctrl+Alt+P で、ペインの固定を切り替えます。

幅が足りないペインはアイコンに畳まれ、さらに狭いと現在位置と総数の表示に変わります。一覧から、見たいペインを選び直せます。

エージェントを起動したい

新しいペインやタブに出る起動メニューがランチャーです。「新規に起動」「Web」「開発」「案件」が並び、履歴があれば「続きから」も出ます。項目をクリックするか、検索欄に名前を打って選びます。

「新規に起動」には 6 つの項目が並びます。「Claude Code」「Codex」「claude-codex」「Grok」「agy」「Hermes」です。「Grok」は Grok Build を、「agy」は Antigravity の CLI です。claude-codex のモデルは、この 1 行から選びます。

Claude Code、Codex、claude-codex、Grok Build の 4 種は、ランチャーと状態の表示で同じ扱いです。agy は起動できますが、委譲の宛先には指定できません。

キーボードでは ↑↓ で選び、Enter で決めます。Esc は検索語を消します。エージェントを選んで Tab か Shift+Enter を押すと、モデル選択へ進みます。

effort は、推論の深さを指定する設定です。「モデル」「effort」を選び、「起動」を押します。←→ で値を変え、↑↓ か Tab で項目を移ります。「既定」のままなら、CLI の既定値で起動します。

claude-codex のモデルは、パネルを開くたびに claude-codex の設定から読み込みます。設定で足したモデルも、そのまま並びます。

区分並ぶもの
「新規に起動」上の 6 項目から、新しい会話を始めます。
「Web」ChatGPT、Gemini、Grok、Claude.ai、NotebookLM、Browser です。
「開発」登録した開発用フォルダです。
「案件」登録した案件用フォルダです。
「続きから」履歴から再開する候補です。設定で表示を切り替えます。

Grok Build には公開されたモデルの一覧がないため、モデルの行は打ち込む欄になります。

Hermes にはモデルと effort の行がありません。使うモデルは Hermes 側の設定に従います。

Web サービスを横に置く

「Web」には 6 つの項目が並びます。5 つの Web サービスと、任意のページを開く Browser です。サービスは ChatGPT、Gemini、Grok、Claude.ai、NotebookLM です。

端末の横で調べ物や資料を確かめるための入口です。ログインが途中で止まるときは、表示される「別の窓でログイン」を使います。

ChatGPT、Gemini、Claude.ai、NotebookLM は、Google ログインの保存先を共有します。Grok は X のログインなので別です。「別の窓でログイン」で開いた窓を閉じると、Web ペインが開き直ります。

Web ペインで落としたファイルは ~/.mycmux/handoff/web/ の下に受け取ります。同じ名前のファイルは -2、-3 と番号が付きます。

開発や案件のフォルダを登録する

「設定 → ランチャー → フォルダを選んで登録…」で、作業フォルダを登録します。ランチャーの「開発」「案件」からフォルダを選び、その後にエージェントを起動します。現在の起動先の表示は、ランチャーの下部です。

「候補」に出たフォルダは、「開発に登録」「案件に登録」で追加できます。初期設定の自動ルールは候補を出すだけで、登録行を勝手には増やしません。

ランチャーの項目を自分で足すには、~/.mycmux/bin/launcher.local.ps1（macOS は launcher.local.sh）に書きます。このファイルはアプリの更新で上書きされません。

ランチャー項目の全一覧は、README（付録 B）にあります。

一覧操作と並び方
手動の登録行表示名を変え、「↑」「↓」で順番を変えます。
自動の登録行新しい順です。「固定」で手動の行に移せます。
「候補」「開発に登録」「案件に登録」で、選んだ分だけ登録します。
「無視」次の走査から、同じ場所を候補に出さないようにします。

自動登録には、git リポジトリ、ファイル更新、動かした場所、セッションで触れた場所の 4 種があります。ルールごとに「候補にする」か「自動で登録する」を選びます。「今すぐ走査」でも更新できます。

設定の正本は ~/.mycmux/launch-dirs.json です。従来の launch-roots.txt は、アプリが書き出すファイルです。

下の画像は、同じ設定画面の上部にある表示項目のチェック欄です。「開発」「案件」の「フォルダを選んで登録…」は、この下にあります。

過去の続きから開く

ランチャーの「続きから」は、直近の会話を開く入口です。広く探すなら、Ctrl+P の Resume を使います。どちらも、アプリに組み込んだセッションの索引を使います。使い方は、エージェントとの作業の「過去の会話を選ぶ」にあります。

ターミナルの出力をたどりたい

端末の出力から、成果物を開く、送った指示へ戻る、文字を探す、長い指示を書く操作です。

端末の表示履歴は 5,000 行です。プロセスが終了すると、終了を示す文字と再起動ボタンが出ます。

出力はディスクにも保存します。終了済みのセッションは保存済みの出力を、生きているセッションは現在の出力を取り直して表示します。

ファイルパスを開く

出力の中にある実在するファイルやフォルダは、そのままリンクです。日本語や空白を含むパスも、途中で折り返されたパスも対象です。クリックすると、対応する文書はプレビューで開き、それ以外は開き方を選べます。

送った指示まで戻る

出力を遡ると、送った指示の位置へ戻るターンチップが出ます。「▲」「▼」で前後の指示へ移り、ラベルを押すと指示の一覧が開きます。エージェントとのやり取りは「会話履歴」からもたどれます。

スクロールバック（端末の過去の出力）はディスクに保存され、再起動後も読み返せます。文字を探すときは Ctrl+Shift+F です。

ターンチップの表示操作
「送った命令の一覧を開く」指示の一覧を開きます。新しい順で最大 200 件です。
「▲」「▼」前後の指示へ移ります。
「会話履歴を開く」会話の記録を開きます。

出力の検索中は Enter で次、Shift+Enter で前へ進みます。Esc で検索を閉じます。

長い指示を書く

ペイン下の専用入力欄へは Ctrl+Alt+I で移ります。Enter で送信、Shift+Enter で改行です。日本語の変換を確定しただけでは送信しません。入力欄の表示は「設定 → 通知とレイアウト → ペインの下に入力欄を出す」で切り替えます。

「Claude メッセージを入力」などの専用入力欄には、最大 10 万文字を書けます。ペインが低くなると自動で隠れるため、見えないときはペインの高さを広げます。シェルへ送る複数行は、1 行にまとめて渡します。

コピー、貼り付け、拡大

端末の基本操作は次のとおりです。

したいこと操作
選んだ文字をコピーするドラッグで選んで離すと、自動でコピーします（3 文字未満は対象外）。
貼り付けるCtrl+V で貼り付けます。長い文は 1024 文字ごとに分けて送ります。
エージェントへ改行だけ送るShift+Enter
端末の文字を拡大縮小するCtrl を押しながらマウスホイールを回します。ウィンドウ全体に効きます。
出力中の URL を開くクリックします。
日本語を入力するIME の変換中はそのまま端末へ渡し、確定の Enter だけでは送信しません。

ホイールで出力を遡れます。Shift を押しながらホイールを回すと、端末の表示履歴を動かします。

入力待ちを見分ける

ペインには状態ドットと、「作業中」「入力待ち」などのラベルが出ます。出力が静かなだけの状態を、完成と取り違えないための表示です。作業が終わったかを確かめる方法は、エージェントとの作業の「終わったかを確かめる」にあります。

ラベル確かめること
「作業中」作業の出力を追います。
「入力待ち」返事や承認が必要か、会話を開きます。
「未確認の枠切れ」使用量の枠と、再開できる時刻を確かめます。
「未確認の入力待ち」まだ見ていない質問や承認を確かめます。
「未確認のエラー」エラーの内容を開いて確かめます。

通常の待機ではラベルが空になる場合もあります。

成果物をプレビューして直したい

ターミナルのパスリンクから、その場で成果物を開きます。

形式対応する拡張子
Markdown md、markdown
HTML html、htm
Word doc、docx、docm、dot、dotx、dotm
Excel xls、xlsx、xlsm、xlsb、xlt、xltx、xltm
PowerPoint ppt、pptx、pptm、pot、potx、potm、pps、ppsx、ppsm
PDF pdf（読むだけ・編集はできません）
テキストとログtxt、log、text（読むだけ）

開いた文書のペインには、形式ごとの印が付きます。エージェントのペインに付いている印と同じ場所なので、並んでいても種類が分かります。

編集の入口は、プレビューの鉛筆のボタン（画面の表記は「この文書を編集」）です。HTML と docx、docm、dotx、dotm に対応し、Ctrl+S で元のファイルへ保存します。Markdown は生のテキストとして編集します。Word の旧形式、Excel、PowerPoint は、アプリ内編集の対象外です。

プレビューで開けない文書は、OS の既定アプリで開く経路へ戻ります。

Markdown は、記号のままではなく本来の形で描きます。表、太字、斜体、インラインコード、番号付きリスト、入れ子、引用、チェックリスト、脚注、画像、水平線に対応します。

紙の色は選んでいるテーマに合わせて変わり、狭いペインでは表が 1 行ずつのカードに組み替わります。

プレビューの中のリンクは押せます。#見出し なら文書の中を移動し、http と https と mailto は既定のブラウザへ渡します。プレビューできる種類のローカルファイルは mycmux の中で開き、それ以外はファイルの場所を表示します。

テキストやログを読む

txt、log、text は、等幅の文字を 80 桁の 1 段組みで表示します。文字コードは BOM、UTF-8、Shift_JIS の順に判定し、UTF-8 以外なら上部に知らせます。文字コードを変えて書き戻すのを避けるため、アプリ内での編集と保存はできません。

本文の Web の URL と絶対パスは、クリックして開けるリンクです。相対パスはリンクにしません。パスの後ろに行番号が付いていても、開くのはファイルだけです。

制御文字や端末の色指定は除いて表示します。5 MB または 50,000 行を超える場合は、先頭の範囲と省略内容を表示します。バイナリ形式のファイルは開かず、理由を知らせます。

macOS でも、HTML の閉じタグをファイルへのリンクと取り違えずに読めます。

HTML のグラフや画像を見る

HTML のプレビューは、ペインに重ねた専用の表示画面で開きます。Windows では WebView2 を使い、重い文書の描画をターミナルから分けています。文書の JavaScript が動くので、グラフや切り替えのある HTML も表示できます。

相対パスで置いた画像も表示できます。タブを切り替えて戻っても、読んでいた位置はそのままです。

このプレビューで開けるのは、成果物の置き場にある文書です。外部リンクは OS の既定ブラウザで開き、ログイン画面はプレビュー内では開けません。保存領域も、ほかの Web サービスとは分かれています。

鉛筆ボタンで編集に入るときだけ、従来の表示枠へ自動で切り替わります。編集の入口は、上で説明した「この文書を編集」です。

同じファイルを開き直しても、更新されていなければ読み直しません。読んでいた位置も残ります。

Office 文書の画像を確かめる

Office 文書は、暗いテーマでも白い紙の見た目で表示します。

Word と PowerPoint では、文書に埋め込まれた画像を表示します。この PC 内のファイルを指すリンク画像も対象です。対応しない画像形式や見つからない画像は、表示できない理由を残します。

Web 上の画像は自動で取りに行かず、参照先のホスト名を表示します。必要な画像は、Word などの元のアプリで確認してください。

図の中の文字は、本文へ混ぜずに図の一部として扱います。

リンク先のローカル画像は、拡張子だけでなく中身が画像かも確認してから読み込みます。

Excel の画像は、セルの位置を再現せず、表の後ろにまとめて並べます。図に説明文があれば、代替テキストとして保持します。グラフは画像ではないため、このプレビューには表示しません。

プレビューと編集のボタン

プレビューの上部用途
形式、ファイル名、親フォルダ開いている文書を確かめます。
「プレビュー」「編集中」「未保存」閲覧中か、保存前の変更があるかを確かめます。
「この文書を編集」対応形式を編集状態にします。
「既定のアプリで開く」外部アプリへ渡します。
「ファイルの場所を表示」文書のあるフォルダを開きます。
「ディスクから読み直す」ファイルの内容を再取得します。
「編集を破棄して閲覧に戻る」編集を終えて閲覧へ戻ります。
編集の操作群主な操作
「ファイル操作」保存、読み直し、編集の破棄です。
「文字の書式」太字、斜体、フォント、文字サイズです。
「段落の書式」揃え方とインデントを変えます。
「文書の構造」見出し、箇条書き、番号付きリストです。
「挿入」リンクと数式です。
「表の編集」行や列を追加、削除します。

保存しても編集状態は続きます。未保存の変更がある文書を閉じると、確認が出ます。Markdown ではファイル操作だけを表示します。
