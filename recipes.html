活用方法

普段の作業に合わせた、8 つの使い方です。状況を選ぶと、画面の名前とキーを見ながら手順を追えます。まだ入れていないなら、はじめるから準備してください。

2 つの視点で差分をレビューしたい

実装の区切りで、同じ差分を Claude Code と Codex の両方に読んでもらいます。頼むのは指摘だけで、書き換えは頼みません。

  1. 作業フォルダのランチャーで「Claude Code」をクリックします。
  2. Ctrl+Alt+D で右に分割します。
  3. 同じフォルダを起動先に選び、「Codex」をクリックします。
  4. 両方に、対象の差分と「ファイルは変更せずレビューして」と伝えます。
  5. 出力を見比べ、片方を読み込むときは Ctrl+Shift+Enter で拡大します。

同じ変更に対する 2 つの指摘が、横に並びます。修正を頼む前に、採用する指摘を決めておくと手戻りが減ります。

引き継ぎ書つきで Codex に任せたい

Claude Code と方針を詰めたあと、続きの実装を Codex に渡します。準備は Python 3 と、公開リポジトリの取得です。

  1. ペインのエージェントに「続きは Codex で」と頼みます。
  2. 引き継ぎ書には、現在地、変更範囲、完了条件を入れるよう伝えます。
  3. 委譲 CLI の spawn で、引き継ぎ書つきの可視ペインとして起動するよう指定します。
  4. 開いたペインで、引き継ぎの内容と始まった作業を確かめます。
  5. 完了したら、指定したファイルとテスト結果を照合します。

委譲先のペインは途中で開けるので、直接指示を足せます。アプリが委譲の方針を強制するわけではないため、エージェント側のルールにも同じ方針を書いておきます。

確認するときは、起動した「Codex」のペイン名を押して開きます。

5 つの会話を見ながら指示を出したい

複数の作業が同時に動いているときは、返事の必要な会話から順に見ます。全ワークスペースをまとめて見る、ダッシュボードの出番です。

  1. Ctrl+Shift+G でダッシュボードを開きます。
  2. 入力欄の上で、列数の 5 を選びます。
  3. 左の一覧から、確かめたいセッションをクリックします。
  4. 入力欄に @ を打ち、指示する相手を選びます。宛先は複数でも構いません。
  5. 送った後、宛先ごとの送達結果を確かめます。

全員へ同じ指示を送っても、誰に届いたかは個別に見られます。Claude Code から質問が出たら、質問カードで答えます。

残して読みたい会話列は「固定」を押します。

翌日に再開し、1 件を別の PC へ渡したい

作業を中断する前に、会話の要点を残しておきます。別の PC で続ける分だけを、受け渡しファイルにします。

  1. タブのペインバーで「セーブポイントを作成」を押します。
  2. 翌日、タイトルバーの「セーブポイントを開く」から記録を選びます。
  3. 「Claude Codeへ渡す」か「Codexへ渡す」で、要点を読ませます。
  4. 別の PC へ渡す記録は、カードの「人に渡す」でファイルにします。
  5. 受け取る PC では「受け取る」を選ぶか、ファイルを mycmux へドロップします。

引き継いだ会話では、整理された前提を確かめてから次の指示を出します。作業フォルダはファイルに含まれないため、必要な実ファイルは別に用意してください。

長く残したい記録には、ピン留めを使ってください。そうでない記録は、最終更新から 48 時間でローカルのゴミ箱へ移ります。

使用量を見てアカウントを切り替えたい

複数のアカウントを持っていて、次の作業に使うログインを選ぶ場面です。切り替えは PC 全体の CLI ログインに効くため、実行中の作業を確かめてから進めます。

  1. タイトルバーの「アカウントと使用量」を開きます。
  2. 取得できた使用量と、その取得時刻を確かめます。
  3. 切り替えるアカウントの行をクリックします。
  4. 実行中のセッションがあれば、警告つきの確認内容を読んでから切り替えます。

選んだアカウントの CLI ログインに切り替わります。mycmux の外で動いている CLI は検知できません。Codex はアカウント別の使用量を取れないため、枠の空き具合の比較には使えません。

コストの内訳を作業種別で見たい

一定期間の作業を振り返り、実装や検証に使った量を確かめる場面です。表示される金額は請求額ではなく、ログと単価から出したコスト相当です。

  1. タイトルバーの「AIログ分析」を開きます。
  2. 期間を「7日」「30日」などから選びます。
  3. 「記録は〜まで」と「未取り込み」を確かめます。
  4. 「何に使ったか」で、作業種別ごとのコスト相当を見ます。
  5. 詳しく見たい作業は、セッション一覧の「主題」から開きます。

作業種別の内訳を見てから、個々の会話へ降りていけます。集計には既知の課題もあるので、元のログを確かめる入口として使います。

Web の調べ物を端末の横に置きたい

ChatGPT や Gemini で調べながら、隣の端末で実装を進めます。NotebookLM で資料を確かめるときも、同じ導線です。

  1. 端末で Ctrl+Alt+D を押します。
  2. 新しいタブのランチャーで、「Web」からサービスを選びます。
  3. ログインが要るなら画面に従います。途中で止まったら「別の窓でログイン」を使います。
  4. Web の内容を見ながら、隣の端末で作業を続けます。

Web の画面は、ワークスペースの中にそのまま置けます。5 つの Web サービスと、任意のページを開く Browser から選べます。サービスは ChatGPT、Gemini、Grok、Claude.ai、NotebookLM です。

案件ごとのワークスペースをすぐ立ち上げたい

複数のリポジトリや案件を行き来していて、毎回フォルダを探す手間を減らしたい場面です。先に「開発」「案件」の一覧へ登録しておきます。

  1. 「設定 → ランチャー」で「フォルダを選んで登録…」を押します。
  2. 必要なフォルダを登録し、表示名を分かりやすい名前にします。
  3. Ctrl+Shift+N でワークスペースを作ります。
  4. ランチャーの「開発」「案件」で目的のフォルダを選び、エージェントを起動します。
  5. サイドバーのワークスペース名をダブルクリックして、名前を付けます。

案件ごとに作業場所が分かれ、Ctrl+Tab で次のワークスペースへ移れます。「候補」から登録する方法や、区分名の変更も使えます。
